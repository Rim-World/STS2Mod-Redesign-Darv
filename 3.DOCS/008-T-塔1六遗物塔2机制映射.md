# 008-T 塔1六遗物塔2机制映射

> 状态：定稿 v1.0（2026-08-23）。来源：塔2 反编译 `2.STS2-111Reference\decompiled` + 塔1 Java 源码对照。**6 件全部"直接可行"**——塔2 引擎存在完整对位机制且有现成模板。

## 背景：塔2 稀有度与遗物架构

- 塔2 **没有 BOSS 稀有度**：`RelicRarity` = None/Starter/Common/Uncommon/Rare/Shop/Event/**Ancient**（`Entities.Relics\RelicRarity.cs`）。塔1 全部 BOSS 遗物在塔2 均为 **Ancient（先古）**——Ancient 即塔2 的 BOSS 级（106 处 Ancient 遗物实证）。
- 遗物继承 `RelicModel : AbstractModel`，玩法钩子 = AbstractModel 上的 virtual 方法，由 `Hooks\Hook.cs` 静态分发。

## 1. 符文立方体 RunicCube（失血抽 1 张）

- 塔1：onLoseHp → DrawCardAction(1)。
- 塔2：失血通知链 `Commands\CreatureCmd.cs`：`Hook.AfterDamageReceived(..., DamageResult.UnblockedDamage)`（L416）/ `AfterCurrentHpChanged(负 delta)`（L404）。抽牌 `CardPileCmd.Draw(choiceContext, count, player)`（`CardPileCmd.cs:969/982`）。
- 模板：RedSkull.cs（血量钩子）、Tingsha.cs（hook 内执行命令）。
- 评级：✅ **直接可行**。选 `AfterDamageReceived`（仅战斗内分发、治疗不触发，最贴塔1 语义）。

## 2. 痛楚印记 MarkOfPain（+1 能量上限；开局 2×Wound 入抽牌堆）

- 塔2 对位：
  - 能量上限：`ModifyMaxEnergy(Player, decimal)`（`AbstractModel.cs:1771`）——模板 **PhilosophersStone.cs:32-39**（塔1 BOSS → 塔2 Ancient）。
  - 开场塞状态牌：**`TeaOfDiscourtesy.cs:56-64` 即现成同类遗物**——`BeforeCombatStart()` + `CardPileCmd.AddToCombatAndPreview<Dazed>(Owner.Creature, PileType.Draw, count, Owner, CardPilePosition.Random)`。
  - **Wound（伤口）存在于塔2**：`Models\Cards\Wound.cs`（无费用、不可打出），状态牌卡池 `StatusCardPool.cs:18-35` 共 12 种状态牌。
- 评级：✅ **直接可行**（逐字仿 PhilosophersStone + TeaOfDiscourtesy）。
- **机制差异（已修正，2026-08-23）**：塔1 的 Wound（伤口）**同样没有虚无**（塔1 `Wound.java` 构造器无 ethereal，零命中；塔1 的 Dazed 眩晕才有虚无）——塔1/塔2 的伤口行为一致：不可打出、无费用、回合结束留在手牌直到被弃/洗回循环。因此痛楚印记的负面强度在塔2 与塔1 基本一致，**效果可直接照搬**（用户已确认）。塔2 的应对手段更多（故障机器人的 Compact/FlakCannon 可转化/利用状态牌），交互面更丰富，属正面差异。

## 3. 悬浮风筝 HoveringKite（每回合首次手动弃牌 +1 能量）

- 塔2 对位：
  - 弃牌钩子 `AfterCardDiscarded`（`AbstractModel.cs:384`）**仅由主动弃牌触发**（`CardCmd.cs:194`）；回合结束自动弃牌走 `CombatManager.FlushPlayerHand`（L1780-1814）**不触发该钩子**——语义与塔1 onManualDiscard 几乎一致 ✓。
  - 能量：`PlayerCmd.GainEnergy(decimal, Player)`（`PlayerCmd.cs:29`）。
  - 每回合标记模式：ArtOfWar.cs（回合布尔 + AfterSideTurnEnd 轮转）/ HappyFlower.cs（回合计数）。
- 模板：Tingsha.cs（弃牌钩子，含"仅自己回合"防御写法）、ArtOfWar.cs。
- 评级：✅ **直接可行**（自行实现"每回合首次"标记，标准模式）。

## 4. 袖剑 WristBlade（0 费攻击伤害 +4）

- 塔1 源码确认：`RelicTier.BOSS`（Silent 的 BOSS 遗物）。
- 塔2 对位：
  - 加法伤害修改 `ModifyDamageAdditive`（`AbstractModel.cs:1579`）——模板 **StrikeDummy.cs:19-38**（打击牌 +3：`props.IsPoweredAttack()` + 来源归属判断）。
  - 0 费判定（塔2 写法）：`!card.EnergyCost.CostsX && card.EnergyCost.GetWithModifiers(CostModifiers.All) == 0`（AllForOne.cs:38、PowerCell.cs:26）。
- 评级：✅ **直接可行**（一处语义适配）。
- ⚠️ **星费体系**（塔2 新机制）：塔2 卡牌有能量费 + 星费（CardModel.cs:49-64）。需决策"星费 > 0 的卡是否算 0 费攻击"（建议沿用 AllForOne 的能量费判定，星费攻击牌极少）；必须用 `GetWithModifiers(All)` 取当前实际费用（费用可临时变化）。

## 5. 核能电池 NuclearBattery（开场充 1 个等离子球）

- 塔2 对位：**PlasmaOrb 存在**（`Models\Orbs\PlasmaOrb.cs`，被动 +1 能量/激发 +2 能量，与塔1 一致）；充能 `OrbCmd.Channel<T>`（`OrbCmd.cs:57`）；开场充球模板 **CrackedCore.cs:29-38**（`BeforeSideTurnStart` + `TurnNumber <= 1`）。
- 评级：✅ **直接可行**。球体系为故障机器人角色机制（Defect.cs:63 BaseOrbSlotCount=3）——但本遗物只出现在故障机器人玩家面前（角色专属池），球栏位天然存在，无跨角色问题 ✓。
- ⚠️ 若将来允许其他角色获得（如交换设置），需确认非故障机器人角色是否有球栏位（未确认，实现期验证）。

## 6. 机械臂 Inserter（每 2 回合 +1 充能球栏位）

- 塔2 对位：`OrbCmd.AddSlots(Player, int)`（`OrbCmd.cs:23`）——模板 **RunicCapacitor.cs:18-25**；回合计数模板 **HappyFlower.cs**（`[SavedProperty] TurnsSeen` + `AfterSideTurnStart` 累加 + 归零触发 + AfterCombatEnd 复位）。
- 评级：✅ **直接可行**。

## 特别说明：塔2 状态牌体系（对痛楚印记的意义）

- 12 种状态牌（Beckon/Burn/Dazed/Debris/FranticEscape/Infection/Wither/Slimed/Soot/Toxic/Void/Wound），多为"回合结束在手牌则惩罚"机制。
- 塔2 的 Wound 目前无玩家侧来源（敌人 Vantom 等会施加）——痛楚印记将是玩家侧第一个 Wound 来源，与塔1 定位一致。
- 塔1 的 Wound 与塔2 的 Wound 行为一致（均不可打出、无费用、**无虚无**，塔1 的 Dazed 才是虚无卡）——效果照搬无机制落差。
- 状态牌体系在塔2 主要服务故障机器人的玩法闭环（Compact 转化、FlakCannon 增伤、RocketPunch 检查、Turbo/CollisionCourse 自产）——印证用户所述"战士的状态牌体系移植给了故障机器人"。
