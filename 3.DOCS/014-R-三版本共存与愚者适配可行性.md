# 三版本共存与「愚者」适配可行性考察

- 日期：2026-11-13 23:27 CST
- 目标：一个 mod 发布包同时支持游戏 v0.107（default）、v0.111（public beta）与 v0.113（public beta）；v0.107 / v0.111 行为不变；在 113 版本加入官方新角色「愚者（Fool）」的达弗适配。
- 方式：三版本反编译源码比对、缓存程序集编译矩阵、IL 成员引用审计；未启动游戏。
- 结论：**可行，但有一个硬约束**。同一个 DLL 不能直接绑定 `RelicOption`；必须用反射垫片。满足该约束后，单 DLL 三版本共存可行。愚者的「先古版三件套」方案可行；若要做箭矢 / 旋律专属机制，需要额外的 113 专用程序集或反射补丁，不能再保持「一个普通 DLL 通吃」。

> 版本说明（2026-11-13 用户澄清）：「103」是「113 游戏版本」的口误，不是 mod v1.0.3。三版本指游戏 0.107 / 0.111 / 0.113。当前不发布，愚者内容尚未实施。

## 1. 可行性结论

| 目标 | 可行性 | 关键条件 |
|---|---|---|
| 一个 DLL 在 107 / 111 / 113 加载 | 高 | 用反射垫片替代 `RelicOption` 直接调用 |
| 107 / 111 行为与 v1.0.0 一致 | 高 | 所有新增过滤在旧版本为无操作；随机数调用顺序不变 |
| 113 五职业恢复自定义三槽位 | 高 | 垫片 + `IsAllowed` 过滤 + `AllPossibleOptions` 立即求值 |
| 113 愚者回落原版 | 高 | 垫片后 `VanillaFallbackPool` 可直接运行；补 `AllowedOptions` 语义 |
| 113 愚者使用自定义三槽位 | 中高 | 用字符串识别 `FOOL`，不引用 113 专属类型 |
| 愚者专属箭矢 / 旋律遗物 | 中 | 需要 113 专用程序集或运行时 Harmony / 反射；不能在旧版本类型加载时出现 113 专属 override |
| 单发布包同时含以上全部 | 中高 | 推荐「通用核心 + 泛用效果」；箭矢专属作为可选进阶 |

## 3. 单 DLL 三版本共存

### 3.1 硬约束

**约束一：`RelicOption` 不能直接调用。**

- 面向 107 / 111 编译 → 三参 MemberRef；113 没有 → `MissingMethodException`。
- 面向 113 编译 → 两参 MemberRef；107 / 111 没有 → `MissingMethodException`。
- C# 可选参数在调用点填默认值，所以「少写一个参数」不能绕开。

**约束二：通用 DLL 不能引用 113 专属类型。**

以下类型 / 成员在 107 / 111 不存在：

- `MegaCrit.Sts2.Core.Models.Characters.Fool`
- `MegaCrit.Sts2.Core.Commands.ArrowCmd`
- `MegaCrit.Sts2.Core.Entities.FoolArrows.*`
- `AbstractModel.AfterArrowShot / AfterArrowImpaled / AfterArrowDislodged`
- `CardTag.Wah / Cho / Ki / Shoot`
- `RelicModel.ArrowHoverTip`
- `ConductorsBaton`、`Twine`、`Fertilizer`、`FoolRelicPool` 等 113 新类型
- `RelicModel.IsAllowedInternal`（113 新增的 protected virtual）

如果通用 DLL 里的某个 `RelicModel` 子类 `override` 了 `AfterArrow*`，在 107 / 111 加载该类型时基类没有对应虚方法，存在 `TypeLoadException` 风险。因此：

- 通用 DLL 的愚者遗物只能使用 107 / 111 / 113 都存在的钩子与类型；
- 需要箭矢专属机制时，另建 113 专用程序集或运行时补丁。

### 3.2 推荐架构：通用核心 + 兼容垫片

```text
ModEntry
├── GameCompat
│   ├── RelicOptionCompat       反射调用 2/3 参 RelicOption
│   ├── CharacterPresence       Type.GetType("...Fool, sts2") 判断愚者是否存在
│   └── RelicFilter             统一调用 RelicModel.IsAllowed(RunState)
├── DarvOptionPool              三槽位；池抽取前过滤 IsAllowed
├── VanillaFallbackPool         原版复刻；选件后过滤 IsAllowed
├── DarvAllPossibleOptions      立即求值；愚者遗物按存在性追加
└── Patches                     现有补丁 + 镜像时序修复
```

`RelicOptionCompat` 原型（已在 107 / 111 / 113 缓存程序集编译通过）：

```csharp
private static readonly MethodInfo? WithDonePage = typeof(AncientEventModel).GetMethod(
    "RelicOption", BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic, null,
    new[] { typeof(RelicModel), typeof(string), typeof(string) }, null);

private static readonly MethodInfo? WithoutDonePage = typeof(AncientEventModel).GetMethod(
    "RelicOption", BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic, null,
    new[] { typeof(RelicModel), typeof(string) }, null);

public static EventOption Create(AncientEventModel darv, RelicModel relic)
{
    var target = WithDonePage ?? WithoutDonePage
        ?? throw new MissingMethodException("AncientEventModel.RelicOption not found.");
    var args = target == WithDonePage
        ? new object?[] { relic, "INITIAL", null }
        : new object?[] { relic, "INITIAL" };
    try { return (EventOption)target.Invoke(darv, args)!; }
    catch (TargetInvocationException e) when (e.InnerException != null) { throw e.InnerException; }
}
```

要点：

- 垫片自身不产生 `RelicOption` MemberRef，IL 中只有 `GetMethod("RelicOption", ...)` 字符串；
- 三参调用显式传 `customDonePage = null`，与 107 / 111 的默认值一致；
- 事件级调用频率极低，反射开销可忽略；
- 若未来 114 再改签名，垫片会抛明确异常，不会静默错位。

### 3.3 为什么不建议三份 DLL

Steam 创意工坊一个条目只分发一份内容，游戏分支共享同一份文件。三份 DLL 需要：

- 三个工坊条目，或
- 一个引导 DLL + 多个版本 DLL（加载器扫描、依赖解析、重复加载风险），或
- 玩家手动替换文件。

这三种都比「单 DLL + 垫片」维护成本高。推荐单 DLL。

### 3.4 编译基线

推荐继续用 **v0.111 的 `sts2.dll`** 作为编译基线（与 v1.0.0 相同），原因是：

- 107 / 111 行为已经被 v1.0.0 验证；
- 113 的差异用垫片与运行时判断处理；
- 若用 113 编译，必须逐项确认没有绑定 113 新重载。当前 143 项引用差集只有 `RelicOption`，但这是基于现有代码；新增愚者代码后需重跑审计。

构建机需要各版本的 `sts2.dll`。本机 `9.SRC/DarvRelicPoolMod/.godot/mono/temp/obj/Debug/PublicizedAssemblies/` 缓存了 107 / 111 / 113 三个 publicized 程序集，可用于本地编译矩阵；干净环境需从对应游戏分支获取。

## 4. 107 / 111 行为不变的保证

| 机制 | 107 / 111 结果 | 说明 |
|---|---|---|
| `RelicOptionCompat` | 命中三参，传 `null` | 与旧直接调用等价 |
| `IsAllowed` 过滤 | 永远 `true` | 107 / 111 的 `RelicModel.IsAllowed` 默认实现返回 `true`，无遗物 override |
| 槽位池过滤顺序 | 无删除，`NextItem` 列表不变 | 随机数序列不变 |
| 回退过滤 | 无删除 | 同上 |
| 设置新增字段 | 未使用 | JSON 反序列化缺字段时保留属性初始值 |
| 愚者内容 | 存在性判断为 `false`，不显示、不进入池 | 需要避免在旧版本 compendium 中出现 |
| 镜像补丁修复 | 仅在 `Model` 未就绪时改变路径 | 旧版本若本来就就绪，行为不变 |

**必须避免的「隐性行为变化」**：

1. 不要在 107 / 111 上把愚者遗物加入 `Darv.AllPossibleOptions`；
2. 不要改变五职业现有槽位池的顺序（`NextItem` 按下标取，顺序即概率）；
3. 不要在旧版本显示第六个职业开关；
4. 不要新增会进入 `RelicGrabBag` 的角色池注册；
5. 不要改 `DarvSettings` 现有字段默认值。

## 5. 愚者适配

### 5.1 识别与开关

- 用字符串识别，不引用 `Fool` 类型：
  - 运行时角色：`owner.Character.Id.Entry == "FOOL"`；
  - 内容存在性：`Type.GetType("MegaCrit.Sts2.Core.Models.Characters.Fool, sts2") != null`；
  - 旧版本遗物查找：按 `Id.Entry` 字符串，如 `"CONDUCTORS_BATON"`。
- `DarvSettings` 新增 `FoolEnabled`：内容完成后默认 `true`；当前内容未实施，保持回退，不改变现状。
- `DarvSettingsUi` 新增第六个职业开关；仅当愚者类型存在时显示。
- `IsEnabledForCharacter("FOOL")` 返回 `FoolEnabled`；关闭时走 `VanillaFallbackPool`。
- `IsKnownCharacter` 增加 `"FOOL"`；仅当内容存在且开关开启时进入自定义池。

### 5.2 槽位 3 的三条设计路线

| 路线 | 内容 | 工作量 | 风险 | 适用 |
|---|---|---|---|---|
| A. 愚者稀有遗物的先古版 | 取愚者 3 件 Rare：`ConductorsBaton`、`Fertilizer`、`Twine`，各做 1 件 Ancient 加强版；与稀有版双向互斥 | 中 | 中 | **已选定**（2026-11-13 用户确认）；与现有储君 / 亡灵模式一致 |
| B. 全新愚者主题遗物 | 2–3 件原创遗物，箭矢 / 旋律 / 情绪主题 | 中高 | 中高 | 想要差异化设计时 |
| C. 复用现有 12 件池 | 把愚者映射到现有 2 件（如静默组） | 低 | 低 | 只做兼容、不做内容时 |

路线 A 的复用点：

- `[RegisterRelic(typeof(DarvModRelicPool))]` + `Rarity = Ancient`；
- `AfterObtained` 里 `Owner.RelicGrabBag.Remove(...)` 移除稀有版；
- 槽位池构建时用 `HasRelic` 按 `Id.Entry` 剔除已持有稀有版；
- `DarvAllPossibleOptions` 追加 3 件；
- 图鉴颜色、排序、互斥逻辑沿用现有 6 件先古遗物的写法。

路线 A 的机制约束：

- `ConductorsBaton` 原效果依赖 `MelodyCmd`（113 专属），`Twine` 依赖 `AfterArrowDislodged`（113 专属）；
- 通用 DLL 不能直接引用这些。若坚持「原效果加强版」，需要 113 专用程序集；
- 若接受「泛用效果 + 愚者主题命名」，可用 107 / 111 / 113 都存在的钩子（`AfterCardPlayed`、`AfterShuffle`、`AfterSideTurnStart`、`AfterCardGeneratedForCombat`、`AfterRoomEntered` 等）实现，保持单 DLL。

### 5.3 箭矢 / 旋律专属机制的三种实现

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 1. 泛用效果 | 遗物只用跨版本钩子；箭矢只作为文案主题 | 单 DLL，风险最低 | 机制不完全贴合愚者 |
| 2. 113 专用伴随程序集 | 通用核心 DLL + `FoolContent.bin`（非 `.dll` 扩展名，避免加载器自动扫描），113 下用 `Assembly.Load(byte[])` 加载并注册 | 可用 `ArrowCmd` / `MelodyCmd` / 113 遗物类型 | 打包、加载、依赖解析复杂；需防止旧版本误加载 |
| 3. 运行时 Harmony / 反射 | 通用遗物类只做泛用效果；用 Harmony patch `AbstractModel.AfterArrow*`，或以反射调用 113 API | 单 DLL | 补丁签名 / 类型解析复杂，调试困难 |

推荐：路线 A 已选定；实现先走**方案 1（泛用效果）**。如果箭矢机制是核心卖点，再评估方案 2。当前不发布，实施时间待定。

### 5.4 图鉴、排序、光效、本地化

- `DarvAllPossibleOptions`：追加愚者 3 件；旧版本按愚者存在性跳过。
- `RelicCollectionSortPatcher`：新增愚者组顺序；`DefaultOrder` / `SwappedOrder` 需要同步。
- `RelicCollectionOutlinePatcher`：新增愚者 ID → 颜色映射。代码事实：`FoolRelicPool.LabOutlineColor` 与 `FoolPotionPool.LabOutlineColor` 在 113 都是 `StsColors.red`，与铁甲相同；但 `Fool.NameColor` 是 `StsColors.yellow`，卡框是 `card_frame_yellow`，且愚者多处颜色字段与铁甲逐字相同（`DialogueColor = 590700`、`RemoteTargetingLineColor = E15847FF`、`RemoteTargetingLineOutline = 801212FF`）。另有 `FOOL.aromaPrinciple`、`FOOL.bestiaryQuote` 等本地化仍为「制作中」，`VfxColor.Fool` 的气泡色相为 0.58（蓝系）。这些迹象支持「红色是复制铁甲后的占位/未完成」，不是角色主色。**设计采用黄色 / 金色主色**，红色只作为次要强调色候选。
- 图标：可复用 113 官方图集帧（`IconBaseName`）或自制 PNG；若复用，`NRelicMirrorPatcher` 的 `ANCIENT_` 前缀会覆盖。
- 本地化：`eng` / `zhs` / `zht` 三份 `relics.json` 与 `settings` 文案；113 新增 `ara` / `ind` 可继续回退英文。
- 设置页第六个开关：需要 `character.fool`、`toggle.fool.label/description` 三语键。

## 7. 风险清单

1. **类型加载风险**：通用 DLL 中任何 113 专属 override / 字段都会在旧版本类型加载时失败。新增愚者代码必须逐类审计。
2. **`RelicOption` 未来再变**：垫片按参数类型查找；若 114 改成别的签名，需更新。垫片抛明确异常，便于定位。
3. **`AllowedOptions` 语义**：v0.113 的过滤发生在「每集合选出一件之后」；自行实现时要保持同一顺序，否则 Blitz 概率不同。
4. **`IsAllowedInternal`**：不能为自定义遗物 override（旧版本无此方法）。若新模式需要按遗物 ID 禁用，只能依赖 `IsAllowed` 的 `RelicLists` 或运行时 Harmony。
5. **愚者遗物注册污染**：`[RegisterRelic]` 会在旧版本注册类型；虽然不进角色池，但可能出现在第三方「全部遗物」UI。可在图鉴层过滤，无法完全阻止第三方遍历。
6. **图鉴颜色**：113 代码给愚者遗物池 / 药水池的 `LabOutlineColor` 是红色，与铁甲冲突；但角色名称色、卡框、能量相关色均为黄色系，红色很可能是复制铁甲后的占位。设计采用黄色，不跟随红色。
7. **联机**：现有 mod 未仔细测试联机；愚者加入后，各玩家按自己的设置生成选项，可能出现不同步的选项集。保持现状并标注风险。
8. **无自动化测试**：本项目没有测试宿主；所有游戏内行为只能手动回归。
