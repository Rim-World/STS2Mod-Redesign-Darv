# v0.113.0 兼容性与「愚者」回落核查

> 2026-11-14 更新：以下失效点已在 mod 1.0.1 修复；修复记录见 `015-T-v0.113最小兼容修复.md`。本文保留当时的诊断证据。

- 日期：2026-11-13 23:27 CST
- 游戏版本：v0.113.0（`release_info.json`：commit `16ac0fe3`，2026-11-12）
- 评估对象：本 mod v1.0.0（已安装 DLL，2026-08-26 构建，面向 v0.111 / RitsuLib 0.5.14）
- 评估方式：读取本机 v0.113 运行日志；比对三版本反编译源码与缓存程序集；对旧 DLL 与新编译 DLL 做 sts2 成员引用差集；对 107 / 111 / 113 缓存程序集做编译矩阵。**未启动游戏**。
- 结论：**不兼容**。mod 能在 v0.113 加载并注册内容，但达弗自定义选项生成与 `AllPossibleOptions` 枚举在运行时失效；后者会抛出未被捕获的 `MissingMethodException`，可打断图鉴 / Loadout 面板初始化。

> 本报告更正 `012-R-v0.113兼容性评估.md` 的「未发现失效点」结论。012 只做了源码层静态比对，没有覆盖已编译 DLL 的成员引用绑定。

## 2. 根因：`RelicOption` 三参重载被删除

### 2.1 三版本签名

| 版本 | 非泛型重载 | 泛型重载 |
|---|---|---|
| v0.107 | `RelicOption(RelicModel relic, string pageName = "INITIAL", string? customDonePage = null)`（`AncientEventModel.cs:279`） | `RelicOption<T>(string pageName = "INITIAL", string? customDonePage = null)`（`:268`） |
| v0.111 | 同上（`AncientEventModel.cs:279`） | 同上（`:268`） |
| v0.113 | `RelicOption(RelicModel relic, string pageName = "INITIAL")`（`AncientEventModel.cs:259`） | `RelicOption<T>(string pageName = "INITIAL")`（`:248`） |

C# 在调用带可选参数的方法时，会把默认值填入调用点。因此 mod 源码里的 `darv.RelicOption(relic)` 在面向 107 / 111 编译时，生成的是**三参 MemberRef**：

```text
AncientEventModel::RelicOption(RelicModel, string, string)
```

v0.113 只剩两参方法。CLR 在首次执行该调用点时抛 `MissingMethodException`。

### 2.2 旧 DLL 与新编译 DLL 的成员引用差集

方法：用 `ilspycmd -il` 导出两个 DLL 的 IL，正则提取全部 `[sts2]类型::成员(签名)`，归一化后做差集。

| DLL | 编译目标 | 唯一 sts2 成员引用数 |
|---|---|---|
| 已安装 v1.0.0 DLL | v0.111 | 143 |
| 当前源码重新编译 | v0.113 | 143 |

差集只有一项：

```text
仅旧 DLL：AncientEventModel::RelicOption(RelicModel, string, string)
仅新 DLL：AncientEventModel::RelicOption(RelicModel, string)
```

这说明：**除 `RelicOption` 外，本 mod 使用的 143 个 sts2 成员在 111 与 113 之间签名一致**。问题集中在一个调用点族，不是大面积 API 崩坏。

### 2.3 影响面

`RelicOption` 在 mod 中有 5 处直接调用：

| 文件 | 行 | 场景 |
|---|---|---|
| `DarvOptionPool.cs` | 67、68（经 `MakeRelicOption`） | 槽位 1、2 |
| `DarvOptionPool.cs` | 134、138（经 `MakeRelicOption`） | 槽位 3 |
| `DarvOptionPool.cs` | 153（经 `MakeDustyTomeOption`） | 槽位 3 魔典 |
| `VanillaFallbackPool.cs` | 25 | 回退：每个原版集合 |
| `VanillaFallbackPool.cs` | 40 | 回退：魔典 |
| `DarvAllPossibleOptions.cs` | 49 | 图鉴 / 控制台枚举 |

其中 `DarvOptionPool.Generate` 是普通方法，调用链在 `DarvOptionsPatcher.Prefix` 的 `try/catch` 内（`Patches/DarvOptionsPatcher.cs:23-36`）。按代码结构，异常应被捕获，Prefix 返回 `true`，游戏执行原版 113 方法；该路径**未在本次日志中实机触发**。结果是：

- 按此路径，达弗事件不会崩溃，但**自定义三槽位逻辑完全失效**，退回原版；
- 抛异常前已经消耗了 `darv.Rng` 的若干随机数（槽位 1 / 回退第一件遗物的 `NextItem`），原版随后用同一 RNG 继续生成，**结果与纯原版不一致**；
- 每次进入达弗都会写一条 `Log.Error`。

## 3. `AllPossibleOptions`：异常逃出 try/catch

`DarvAllPossibleOptions.Build` 是迭代器（`yield return`，`DarvAllPossibleOptions.cs:45-51`）。`Prefix` 里的 `try` 只包住「创建迭代器」这一步：

```csharp
try
{
    __result = DarvAllPossibleOptions.Build(__instance); // 只创建迭代器，不执行方法体
    return false;
}
catch (Exception e) { ... }
```

真正的 `darv.RelicOption(...)` 在调用方枚举时才执行，此时已经离开 `Prefix` 的 `try`。日志证实：

```text
godot2026-11-13T23.08.10.log:878
ERROR: [Loadout] Failed to initialize loadout panel items; initialization will not be retried:
System.MissingMethodException: Method not found: '...AncientEventModel.RelicOption(RelicModel, String, String)'.
   at DarvRelicPoolMod.DarvAllPossibleOptions.Build(Darv darv)+MoveNext()
   ...
   at Loadout.PanelItems.LoadoutBag.BuildRelicGroupingData()
```

原版还有两个消费者会枚举该方法：

- `NRelicCollectionCategory.LoadRelics`（`MegaCrit.Sts2.Core.Nodes.Screens.RelicCollection/NRelicCollectionCategory.cs:195`）——图鉴「先古 → 达弗」子分类；
- `AncientConsoleCmd`（`.../DevConsole.ConsoleCommands/AncientConsoleCmd.cs:41、71`）——控制台 `ancient` 命令补全与校验。

因此该异常不是 Loadout 专属；打开原版遗物图鉴也可能在同一处失败。当前日志只捕获到 Loadout 的调用，原版图鉴路径**未在日志中出现**，标记为未确认。

## 4. 「愚者」回落核查

### 4.1 路径选择：会进入回退分支

- `Fool` 是官方角色，类型 `MegaCrit.Sts2.Core.Models.Characters.Fool`，`ModelDb.AllCharacters` 在 113 包含 6 个角色（`ModelDb.cs:146-153`）；官方中文名「愚者」见 `localization/zhs/characters.json:39`。
- 角色 ID 由 `ModelDb.GetEntry` → `StringHelper.Slugify(type.Name)` 生成（`ModelDb.cs:563`、`StringHelper.cs:95`）。`Fool` → `FOOL`。
- `DarvOptionPool.IsKnownCharacter` 只认 `IRONCLAD / SILENT / DEFECT / REGENT / NECROBINDER`（`DarvOptionPool.cs:88-90`）。`FOOL` 不在其中。
- 因此 `DarvOptionPool.Generate` 在 `DarvOptionPool.cs:54` 进入 `VanillaFallbackPool.Generate`。

**路径选择正确。**

### 4.2 回退内容对愚者是否成立

`VanillaFallbackPool` 逐字复刻 111 原版流程（`VanillaFallbackPool.cs:17-45`），依赖的数据在 113 均存在：

- `Darv._validRelicSets` 仍是 11 个集合，内容与 111 逐字一致（`Darv.cs:173` 起）；
- `DustyTome.SetupForPlayer` 签名一致（`DustyTome.cs:51`）；
- 愚者卡池有 90 张卡，其中先古稀有度只有 `DivineShot` 与 `LostLute`（`FoolCardPool.cs:50、73`）；
- `DivineShot` 是 `ArchaicTooth` 的转化卡，被 `HasAncientCards` 排除；`LostLute` 不在转化表中（`ArchaicTooth.cs:26-54`），因此愚者**有可用的先古卡**，魔典分支不会因空池退化。

结论：回退算法本身能为愚者生成 3 个选项，魔典分支可用。

### 4.3 当前二进制下的实际表现

由于 `VanillaFallbackPool.cs:25` 直接调用三参 `RelicOption`，当前 DLL 在回退第一步就抛 `MissingMethodException`。该异常被 `DarvOptionsPatcher` 捕获，游戏执行原版 113 `GenerateInitialOptions`。玩家最终仍会看到原版选项，但：

- 不是「回退代码正常执行」，而是「回退代码失败后由原版兜底」；
- RNG 已被回退代码消耗一部分，选项与纯原版不一致；
- 每次达弗写错误日志。

**判定：路径选择正确，执行不干净；当前版本不能称为「正常回落到原始路径」。**

### 4.4 干净回落还缺一项：113 的 `AllowedOptions`

v0.113 在原版 `GenerateInitialOptions` 中把选项包进 `AllowedOptions`（`Darv.cs:152、164`），按 `RelicOption.Relic.IsAllowed(RunState)` 过滤：

- Blitz 模式禁用 `BlackStar`、`Ectoplasm`（`RelicLists.cs:15-26`）——两者都在 mod 的槽位 1 / 2 池；
- 第三幕后期禁用一批遗物（`RelicLists.cs:63`）。

`VanillaFallbackPool` 没有这层过滤。标准模式对愚者没有影响；Blitz 模式下回退池可能给出被禁遗物。修复方式是在回退和自定义池中统一调用 `relic.IsAllowed(owner.RunState)`：

- v0.107 / v0.111：`RelicModel.IsAllowed` 是虚方法，默认返回 `true`，过滤是无操作，行为不变；
- v0.113：`IsAllowed` 改为非虚，内部检查 Blitz / 第三幕后期，过滤生效。

## 6. 修复建议（未实施）

以下改动都保持 107 / 111 行为不变：

1. **新增 `RelicOptionCompat` 反射垫片**：按参数类型查找三参或两参重载，统一返回 `EventOption`。垫片本身不直接绑定任何 `RelicOption` MemberRef，因此同一 DLL 可在三个版本运行。
   - 原型已在 `TMP/compat-build/` 对 107 / 111 / 113 缓存程序集编译通过；IL 中只剩 `GetMethod("RelicOption", ...)` 字符串，无直接调用。
2. **替换全部直接调用**：`DarvOptionPool`、`VanillaFallbackPool`、`DarvAllPossibleOptions` 统一走垫片。
3. **把 `DarvAllPossibleOptions.Build` 改为立即求值**：返回 `List<EventOption>`，让 `Prefix` 的 `try/catch` 真正覆盖构造过程。
4. **补 `IsAllowed` 过滤**：自定义槽位池在抽取前过滤；回退在每集合选出一件后按原版语义过滤。107 / 111 为无操作。过滤后若池为空，必须有兜底（当前槽位 1 / 2 没有空池保护，113 Blitz 下不会触发，但不能假设未来模式不会）。
5. **修复镜像补丁时序**：`_Ready` 时若 `Model` 未设置，订阅 `ModelChanged`，在模型赋值后再镜像；不要在 `_Ready` 里直接读 getter。
6. **验证**：对 107 / 111 / 113 三个缓存程序集编译；检查新 DLL 无直接 `RelicOption` MemberRef；游戏内按 `3.DOCS/010-T-手动测试方案.md` 回归。**本次未运行游戏**。
