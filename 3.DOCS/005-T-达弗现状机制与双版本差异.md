## 1. 达弗是什么

- 达弗（Darv，**囤积者 The Hoarder**）是《杀戮尖塔2》的**先古之民（Ancients）**事件之一，出现在地图上的先古之民房间（地图图例官方名"先古之民"，`LEGEND_ANCIENT`）。
- 机制一句话：**三选一遗物**。每次进入事件，从符合条件的遗物池中随机抽出 3 个遗物选项（其中第 3 个有 50% 概率被**尘封魔典（DustyTome）**占据），玩家选 1 个获得。
- 代码位置（两版本相同路径）：`MegaCrit.Sts2.Core.Models.Events\Darv.cs`，类 `public class Darv : AncientEventModel`。
- 继承链（两版一致）：`Darv : AncientEventModel : EventModel : AbstractModel`。
- 身份：**全游戏唯一"共享先古之民"**（`ModelDb.AllSharedAncients => [AncientEvent<Darv>()]`，注释 "Notably, we only have 1 right now. That's Darv."）。其余 8 个先古之民分属各幕：第 1 幕（**密林** Overgrowth / **暗港** Underdocks 变体）= [涅奥 Neow]；第 2 幕 **巢穴** Hive = [欧洛巴斯 Orobas, 佩尔 Pael, 特兹卡塔拉 Tezcatara]；第 3 幕 **荣耀** Glory = [诺奴佩普 Nonupeipe, 坦克斯 Tanx, 瓦库 Vakuu]（`DeprecatedAncientEvent` 仅为存档兼容）。**塔2 共 3 幕**（`ModelDb.ActsByIndex`：index 0=第 1 幕 [密林, 暗港]、index 1=第 2 幕 [巢穴]、index 2=第 3 幕 [荣耀]；`ActModel.cs:567-571` 注释 "Act 1 (index 0) is Overgrowth. Act 2 is Hive. Act 3 is Glory."；暗港是第 1 幕的解锁变体），`RunState.CurrentActIndex` 为 **0-based**（0 = 第 1 幕，最大 2 = 第 3 幕/最终幕）。
- 每局出现规则（`RunManager.GenerateRooms()`，107:668-692 / 111:743-767，**两版语义相同**）：
  1. `UnlockState.SharedAncients`（达弗纪元 DarvEpoch 未解锁时为空，达弗被移除）洗牌；
  2. **跳过第 1 幕**（`Acts.Skip(1)`，达弗不会出现在第一幕）；
  3. 对第 2、3 幕**依次**执行"分配"：`count = Rng.UpFront.NextInt(剩余共享池大小 + 1)` 均匀取 0..N 个，`Take(count)` 后 `list = list.Except(取走的)`——**不放回**。池 = [达弗] 时：第 2 幕 `NextInt(2)` → 50% 分到 / 50% 不分；**若第 2 幕已分到则池变空，第 3 幕 `NextInt(1)` 必为 0（必不分到）**；若第 2 幕未分到，第 3 幕再 50% 分到。
  4. 每个被分配的幕里：`ActModel.GenerateRooms` 中 `_rooms.Ancient = rng.NextItem(本幕已解锁先古之民 ∪ 分到的共享子集)`（ActModel.cs:385）——**每幕只有一个先古之民地图节点**，达弗与本幕 3 个先古之民均匀竞争（1/4）。
  - 由此推导（达弗纪元已解锁、幕内 3 个先古之民全部解锁时）：
    - 第 2 幕分到达弗：50%；第 3 幕分到达弗：25%（= 第 2 幕未分 50% × 第 3 幕再分 50%）；整局完全不分：25%。
    - **第 2 幕出现达弗 = 50% × 1/4 = 12.5%**
    - **第 3 幕出现达弗 = 25% × 1/4 = 6.25%**
    - **一局至少出现一次达弗 = 12.5% + 6.25% = 18.75%**（一局内达弗至多出现在一幕）
    - （推导值，非代码内显式权重；若幕内先古之民有未解锁则分母变小、概率略升）
- 解锁：`达弗纪元（DarvEpoch）` 未解锁 → 达弗完全不出现（`UnlockState.SharedAncients` 移除）。解锁条件（`ProgressSaveManager.UpdateEpochsPostRun`）：**除达弗外的所有先古之民（涅奥/欧洛巴斯/佩尔/特兹卡塔拉/坦克斯/瓦库/诺奴佩普）都被访问过**（局后留有 AncientStats）时解锁；达弗自身豁免。
- 进入事件时的通用流程：`EventRoom` → `EventModel.BeginEvent`（设置 Owner 与 Rng）→ `BeforeEventStarted`（**先古之民通用：回复满血**，WearyTraveler 升阶下回 80%）→ `SetInitialEventState` → `GenerateInitialOptionsWrapper`（sealed，内含 `Hook.ShouldAllowAncient` 放行检查与 `ReplaceNullOptions`）→ 子类 `GenerateInitialOptions()`。
- 事件 Rng（EventModel.cs:238）：`new Rng(局种子 + (非共享事件? 玩家槽位 : 0) + hash(事件ID))`——**同一局内每次进入同一事件，Rng 种子完全相同，选项序列（含位置）可完整复现**；跨局种子不同则随机。`NextBool` 严格 50/50、`NextItem` 均匀、`UnstableShuffle` 为 Fisher-Yates。

## 2. 选项生成流程（精确语义，两版本共用逻辑）

`GenerateInitialOptions()`（Darv.cs:147-168）：

```
1. 候选生成：遍历静态 _validRelicSets（List<ValidRelicSet>），
   保留 filter(Owner) == true 的集合，每个集合用 Rng.NextItem(集合.relics) 随机出 1 个遗物候选
   （集合内多个遗物时等概率二选一；单遗物集合则必出该遗物）。
2. 洗牌：候选列表 UnstableShuffle(Rng)（Fisher-Yates，均匀）。
3. 取舍：Rng.NextBool()（严格 50/50）：
   - true  → 取前 2 个候选 + 固定追加尘封魔典（SetupForPlayer 初始化）→ 共 3 选项，魔典恒在第 3 位
   - false → 取前 3 个候选 → 共 3 选项
```

随机源确认（`MegaCrit.Sts2.Core.Random\Rng.cs`）：
- `NextBool()`：`_random.Next(2) == 0`，严格 50/50（行 78-82）。
- `NextItem<T>(IEnumerable<T>)`：`NextInt(0, count)` 均匀（行 255-265）。
- `Shuffle`：Fisher-Yates 均匀洗牌（行 308+）；`UnstableShuffle` 为其变体（`Extensions\ListExtensions.cs:45-60`）。
- 结论：**原版达弗没有"权重"概念，完全是均匀随机**。修改"概率分布"即修改：①候选集合的组成（增删集合/遗物）；②集合内遗物数量（影响二选一/三选一）；③各集合的 filter 条件（影响不同幕的生效池）；④尘封魔典的 50% 掺入逻辑。

## 4. 各遗物展示概率（精确计算，条件概率）

> 集合内含 2 个遗物时（仅 107），单个遗物展示概率 = 集合概率 × 1/2。

## 5. 选项展示位置分布（三选一中的位置）

> 结论先行：**原版中除尘封魔典固定出现在第 3 个选项外，没有任何"某遗物固定某位置"的机制**——普通遗物的位置由均匀洗牌决定。以下为精确位置分布。

### 5.1 UI 位置语义

- 选项渲染：`NEventLayout.cs:372-404` 按事件选项列表**顺序**逐个 `AddChild` 到 `%OptionsContainer`（VBoxContainer，从上到下）——**"第 1 个选项" = 列表第 0 项（最上方），依此类推**。无额外排序。
- 因此展示位置 = `GenerateInitialOptions()` 返回列表的下标。

### 5.2 位置概率（设 N = 当前幕候选数）

生成流程决定：洗牌均匀 → 分支 A（50%）取前 2 个候选 + 尘封魔典**追加到末尾**；分支 B（50%）取前 3 个候选。

对任意候选遗物 X（在其所在集合通过 filter 的前提下）：

| 位置 | 分支 A（50%） | 分支 B（50%） | 合计 |
|---|---|---|---|
| 第 1 个 | 1/N（前 2 位均匀） | 1/N（前 3 位均匀） | **1/N** |
| 第 2 个 | 1/N | 1/N | **1/N** |
| 第 3 个 | 0（被尘封魔典占据） | 1/N | **1/(2N)** |
| 不出现 | — | — | 1 − 2.5/N |

对尘封魔典：

| 位置 | 概率 |
|---|---|
| 第 1 个 | 0 |
| 第 2 个 | 0 |
| 第 3 个 | **50%**（分支 A 时恒在第 3 位） |
| 不出现 | 50% |

**要点**：① 候选遗物出现在第 3 个位置的概率只有第 1/2 个位置的一半（50% 的情况下第 3 位被尘封魔典占据）；② 尘封魔典只要出现就必在第 3 个；③ 第 1 与第 2 个位置完全等价。

### 5.3 各幕数值表（位置概率 = 该遗物出现在该位置的条件概率）

**v0.107**（N=8，第 2/3 幕）：单遗物集合的遗物：位置 1/2 各 **12.5%**（1/8）、位置 3 **6.25%**（1/16）；107 特有的二选一集合（灵体外质/添水、贤者之石/天鹅绒颈圈）：还需 ×1/2 → 位置 1/2 各 **6.25%**、位置 3 **3.125%**。尘封魔典：位置 3 = 50%。

**v0.111**：第 2 幕 N=11：位置 1/2 各 **9.09%**（1/11）、位置 3 **4.55%**（1/22）；第 3 幕 N=9：位置 1/2 各 **11.11%**（1/9）、位置 3 **5.56%**（1/18）。尘封魔典：位置 3 = 50%。

（同样为"达弗已出现"的条件概率；与 §4 的展示概率关系：位置 1 + 位置 2 + 位置 3 = 展示概率 = 2.5/N。）

### 5.4 为什么会有"固定位置"的感觉（重要澄清）

1. **尘封魔典恒在第 3 位**（代码：`list.Add(RelicOption(dustyTome))` 追加到末尾，Darv.cs:161）——这是唯一真实的"固定位置"。
2. **同一局内重进事件，选项序列（含位置）完全复现**：事件 Rng 种子 = `局种子 + hash(达弗ID)`（EventModel.cs:238），同局内每次 `BeginEvent` 都用相同种子从头生成 → 候选抽取、洗牌、NextBool 的结果逐位相同。若玩家在同一局内读档/重进达弗事件，会看到**完全相同**的 3 个选项与位置（跨局则不同）。这是"位置固定感"最可能的来源。
3. 除此之外，原版**没有**"某遗物固定在某个槽位"的设计（无按遗物 ID 排序/分组槽位的逻辑），跨局时位置由均匀洗牌决定。

### 5.5 对 mod 的提示

- 若 mod 自定义选项生成，位置 = 返回列表顺序，可自由实现"固定槽位"（如：第 1 位恒为某遗物、第 3 位恒为尘封魔典等）；若想保持原版手感，按 §5.2 的分布即可。
- 若 mod 希望"每次进入事件选项都不同"（打破同局复现），需要引入 mod 自身的随机流（如 ritsulib 的 `ModRunRngRegistry.Get(runState, modId, streamId)`），不要只用事件 Rng。

## 6. 本地化（两版本完全一致，50 键无差异）

`localization/{eng,zhs}/ancients.json` 中 `DARV.*` 共 50 个键，107 与 111 **逐键逐值一致**，无需双版本适配。要点：
- `DARV.epithet` = "囤积者"（The Hoarder）
- `DARV.title` = "达弗"
- 对话键格式：`DARV.talk.{角色}.{visitIndex}-{行号}.{speaker}`，角色为 ANY/IRONCLAD/SILENT/DEFECT/NECROBINDER/REGENT（任意/铁甲战士/静默猎手/故障机器人/亡灵契约师/储君）；`firstVisitEver` 首次见面。
- 选项界面显示的遗物名/描述来自遗物自己的本地化（relics.json 的 `.title`/`.eventDescription`，缺失时回退 `.description`），非 ancients.json。
- 达弗对话语义（结合 `Darv.cs` 的 `DefineDialogues`）：VisitIndex 0 = 首次见面；1 = 第 2 次；4 = 第 5+ 次（角色专属剧情线，如铁甲战士的重刃、静默猎手的战利品交换等，均为纯文本与音效，不改变选项机制）。
- 达弗相关遗物文本的唯一 107→111 差异：**添水（Sozu）** 描述语序/着色调整（zhs："你无法再获得药水。在每回合开始时获得{E}。" → "在每回合开始时获得{E}。你无法再获得[gold]药水[/gold]。"）。

## 7. 与选项池相关的其它 API 面

- `AllPossibleOptions`（Darv.cs:54-55）：`_validRelicSets.SelectMany(relics) + 尘封魔典` 的只读枚举——UI/图鉴（遗物收集界面的"先古"分类，NRelicCollectionCategory.cs:194）等场景枚举"达弗可能给的所有遗物"。**修改池时如不改这里会出现不一致**。
- `RelicOption`（`AncientEventModel.RelicOption(RelicModel, pageName, customDonePage)`，protected，AncientEventModel.cs:279-288）：事件选项工厂；`OnChosen` = `await RelicCmd.Obtain(relic, Owner)` → `Done()`（写入 Run History 的 AncientChoices → 事件结束）。mod 自写选项生成时可直接复用此 protected 方法（含完成流程）。
- `EventOption`：`EventOption.FromRelic(relic, eventModel, onChosen, textKey)` 可从遗物构造选项（标题/描述/HoverTips 自动取遗物文本，可被事件 loc 覆盖）。
- 遗物稀有度：达弗相关遗物为**先古稀有度**（`RelicRarity.Ancient`，官方译名"先古"：先古之民赐予的遗物），与普通遗物池分离；引入新遗物需注册到事件遗物池 `EventRelicPool`（见 BaseLib "Adding Ancients" 文档）。
- 游戏自身 Hook：`Hook.ShouldAllowAncient(runState, player, ancient)`（蜡质颈圈 Wax Choker 等用）只能整体允许/禁止进入某先古之民，**不能改选项**。
- 尘封魔典（`Relics\DustyTome.cs`，两版逐字节相同）：先古稀有度的塔2 专属遗物；`SetupForPlayer` 从角色卡池的先古稀有度卡（排除古老牙齿 ArchaicTooth 的"超脱"先古卡集合）均匀随机选一张；`AfterObtained` 将其**升级后**加入牌组。塔1 无此遗物（外部资料佐证）。

## 8. 对 mod 的启示（事实，非方案）

1. 达弗选项生成集中在 **1 个实例方法 + 1 个静态字段**：patch `Darv.GenerateInitialOptions`（可整体替换逻辑，实现任意权重/池/幕条件/槽位布局）或替换静态 `_validRelicSets`（保持原逻辑，只改池组成）。
2. 两版本 `Darv.cs` 仅有静态构造器与过滤条件不同；方法体（GenerateInitialOptions/AllPossibleOptions/DefineDialogues）**逐字节一致**，patch 点在两版本间通用。
3. 概率"分布"完全由 `_validRelicSets` 的结构 + filter 决定，天然支持：自定义集合、自定义权重（换用 WeightedNextItem 或自写）、按幕/按角色/按 Modifier 过滤、自定义槽位布局（位置由返回列表顺序决定，见 §5.5）。
4. 引入塔1遗物 = 注册新 RelicModel（含稀有度/池/本地化/图标）+ 把它的模型实例加入达弗候选池。
5. 达弗出现频率：分配环节第 2 幕 50% / 第 3 幕条件 50%（不放回），实际出现概率第 2 幕 12.5%、第 3 幕 6.25%、一局至多一幕（`RunManager.GenerateRooms` + `ActModel.GenerateRooms`）；若想改"出现概率"需另行 patch 这两处（不属于本次"选项概率"范围，仅记录）。
