# v0.113 袖剑补丁修复（1.0.4）

- 日期：2026-11-14 02:14
- 对象：`DarvRelicPoolMod` 1.0.3（已上传工坊）中的 `WristBladeCompatPatcher`
- 结论：**1.0.3 在 107 / 111 / 113 都可能静默丢失袖剑 +4 伤害**；1.0.4 已修复，待实机验证。

## 1. 证据

1.0.3 的 v0.113 实机日志（`%APPDATA%\SlayTheSpire2\logs\godot.log:394-400`）：

```
[DarvRelicPoolMod] [Patcher - darv] Applying 4 patches...
[Critical] darv_wristblade_compat_AbstractModel_ModifyDamageAdditive__1 - Ignored: Target method not found but patch is marked ignorable: AbstractModel.ModifyDamageAdditive
[Patcher - darv] Patch application complete: 3 applied, 1 ignored, 0 failed, 4 total
```

图鉴外观与排序的 5 个补丁全部成功；袖剑补丁被忽略，说明 **113 的 6 参 `ModifyDamageAdditive` 没有被注册**。

## 2. 根因

`WristBladeCompatPatcher` 依赖两件事：

1. 用 `Type.GetType("MegaCrit.Sts2.Core.Entities.Cards.CardPlay, sts2")` 探测 `CardPlay` 类型；
2. 有 `CardPlay` 就注册 6 参目标，否则注册 5 参目标。

实际有两个错误：

- **加载上下文**：Godot 的 mod 加载环境中，`Type.GetType` 的返回值不可靠；1.0.3 实机中它返回 `null`，于是只注册了 5 参目标。113 只有 6 参方法，5 参被忽略。
- **版本判断错误**：107 **也有** `CardPlay` 类型（`MegaCrit.Sts2.Core.Entities.Cards.CardPlay`），只是 `ModifyDamageAdditive` 仍是 5 参。因此“类型存在”不能推出“6 参方法存在”。如果只按类型判断，107 会错误地注册 6 参目标。

## 3. 修复（1.0.4）

`9.SRC/DarvRelicPoolMod/Patches/WristBladeCompatPatcher.cs`：

- `CardPlayType` 改为 `typeof(AbstractModel).Assembly.GetType("...CardPlay", false)`，不依赖程序集限定名和加载上下文。
- 新增 `SixArgMethod`：用 `typeof(AbstractModel).GetMethod("ModifyDamageAdditive", ..., 6 参类型数组)` 检查方法是否真实存在。
- `GetTargets()`：`SixArgMethod != null` 时只注册 6 参；否则只注册 5 参。
- 不再同时注册两条可选目标，因此正常情况下不会再出现 `optional target ignored` 噪音。
