# v0.113.0 兼容性评估：达弗选项生成与遗物过滤

- 日期：2026-11-13
- 评估对象：本 mod v1.0.0（面向 v0.111 构建，依赖 RitsuLib 0.5.14）
- 方式：静态比对 v0.111 / v0.113 反编译源码；用 `ilspycmd` 核对已安装 RitsuLib 的公开 API；只读，未构建、未实机
- 结论：**未发现失效点**。发现两处 v0.113 引入的行为差异，影响范围是「新模式下的遗物过滤」，不是崩溃。
- **2026-11-13 23:27 更正**：上述结论不成立。本报告只做了源码层比对，未检查已编译 DLL 的成员引用绑定。v0.113 删除了三参 `AncientEventModel.RelicOption(RelicModel, string, string)`，已安装 DLL 仍绑定该重载，运行时抛 `MissingMethodException`；`DarvAllPossibleOptions` 因迭代器延迟执行而让异常逃出补丁 `try/catch`。详见 [`013-R-v0.113兼容性与愚者回落核查`](013-R-v0.113兼容性与愚者回落核查.md)。

## 行为差异 1：`AllowedOptions` 过滤被绕过

v0.113 在 `Darv.GenerateInitialOptions` 里把选项包进 `AllowedOptions(...)`（`Darv.cs:152`、`:164`）。该方法按 `option.Relic.IsAllowed(RunState)` 过滤（`AncientEventModel.cs:274`），用于剔除新模式禁用或第三幕后期禁用的遗物（`RelicModel.cs:441`）。

本 mod 用 Prefix 整体替换 `GenerateInitialOptions`，因此：

- 新过滤规则对达弗完全失效，被禁遗物仍可能出现在三个槽位里。
- 本 mod 自定义的 12 件遗物从未参与过滤。

影响：只在启用新过滤规则的模式（如 Blitz）或第三幕后期出现。原版 107/111 语义下与 mod 设计一致。

## 行为差异 2：`IsAllowed` 由虚改非虚

v0.111：`public virtual bool IsAllowed(IRunState runState)`（`RelicModel.cs:434`）。
v0.113：`public bool IsAllowed(IRunState runState)` 调用新增的 `protected virtual bool IsAllowedInternal(IRunState runState)`（`RelicModel.cs:441`、`:458`）。

后果：任何自定义遗物若 `override IsAllowed`，在 v0.113 会因基方法不再可重写而无法加载（`TypeLoadException`）。本项目 12 件遗物均未重写该方法（已全量检索），不受影响。

## 逐参比对：RitsuLib 0.5.14 → 0.6.11（2026-11-13 补测）

方法：用 `ilspycmd -il` 导出两边 IL，把 mod DLL 中发往 `STS2-RitsuLib` 的 MemberRef 全部取出，与 0.6.11 `compat/0.113.0` 四个程序集的 `.method` 定义按「类型 + 成员 + 形参类型列表」逐项匹配。

| 项 | 结果 |
|---|---|
| 本 mod 引用项 | 38 项，覆盖 Settings 页构建、数据持久化、遗物注册、补丁注册 |
| 形参逐一比对 | 38/38 一致。含 7 参 `ModDataStore.Register<T>(string, string, SaveScope, Func<T>, bool, ModDataMigrationConfig, IEnumerable<IMigration>)`、`Get<T>(string)`、`Modify<T>(string, Action<T>)`、`Save(string)`；特性 `RegisterRelicAttribute(Type)`、`RegisterSharedRelicPoolAttribute()` |
| 程序集标识 | mod 引用 `STS2-RitsuLib, Version=0.5.14.0`，无公钥令牌（非强名称）；实装 0.6.11.0 同为非强名称 |
| 类型转发 | 门面 `STS2-RitsuLib.dll` 含 1495 个 `ExportedType` 转发，本 mod 用到的类型全部命中 |
| 泛型约束 | `RegisterPatch<TPatch>` 仍为 `where TPatch : IPatchMethod`；`ModDataStore` 的 `where T : class, new()` 与 `DarvSettings` 相符 |

结论：RitsuLib 侧**二进制兼容**。此前「未逐参验证签名」的未确认项关闭。
