## 实装更改概括

- **三槽位重构**：槽位 1（星盘/潘多拉魔盒/黑星/召唤铃铛/空鸟笼）、槽位 2（添水/灵体外质/贤者之石/天鹅绒颈圈/异蛇之眼）、槽位 3（50% 尘封魔典 / 50% 职业专属池）；符文金字塔在槽位 1、2 各做一次 20% 判定且互斥，合计约 36%。
- **12 件新遗物**：塔1 BOSS 遗物 6 件（铁甲/静默/故障各 2）+ 储君/亡灵先古遗物 6 件，`Rarity = Ancient`，只在达弗出现，不进 `RelicGrabBag`。
- **双向互斥**：已持有稀有版 → 达弗池剔除对应先古版；获得先古版 → 本局该稀有版从宝箱/商店/战斗/事件中移除。
- **设置页**：5 职业开关（关闭回退该版本原版逻辑）、铁甲痛楚印记 ↔ 故障核能电池互换、5 个「槽位 2 异蛇之眼」开关、「保存并退出」唯一落盘、三语（eng/zhs/zht）。
- **图鉴**：角色光效按职业上色（含储君橙/亡灵粉）、子分类按 铁甲→静默→储君→亡灵→故障 排序、先古图标复用官方图集帧并在渲染层翻转。
- **双版本**：107 与 111 行为一致，虚方法签名差异由运行时可选补丁自适应。

## 简略技术细节

- 技术栈：Godot 4.5.1 + C#（net9.0）、`STS2.RitsuLib 0.5.14`（`IPatchMethod`、设置页、数据存储）、`Krafs.Publicizer 2.2.0`（构建期访问 `Darv._validRelicSets`）。
- 核心补丁：`Darv.GenerateInitialOptions` 与 `Darv.AllPossibleOptions` 的 Prefix 整体替换；必选组失败即禁用 mod 行为，可选组（图鉴外观、设置暂存清理、图标镜像）失败不影响玩法。
- 遗物池：自定义 `[RegisterSharedRelicPool] DarvModRelicPool` 只负责把 12 件遗物注册进 `ModelDb`，不参与抽取。
- 设置写入：`DeferredSaveBinding` 让 `Save()` 成为空操作以阻断 RitsuLib 的 0.35s 防抖落盘，写入只落在会话暂存；「保存并退出」才覆盖磁盘并 `NGame.Quit()`。
- 构建：`dotnet build` → Godot `--headless --import` → `--export-pack` → 拷入游戏 `mods/`；pck 资源必须带 `res://DarvRelicPoolMod/` 前缀，`export_filter` 必须是 `selected_resources`。

## 失败经验或实验教训

1. **pck 路径前缀**：去掉 `res://{modId}/` 前缀会让 mod 资源与游戏主 pck 同路径，直接覆盖官方 `relics` 表，且官方合表逻辑根本找不到这些文件。表现是「官方文本全变 key、自己的文本正常」。
2. **虚方法签名靠版本**：`AbstractModel.ModifyDamageAdditive` 107 是 5 参、111 是 6 参。用 `override` 写死一版，另一版**静默失效**（不崩溃、不报错），只能靠玩家实测发现。跨版本差异一律走运行时反射解析的 optional patch。
3. **`override` 属性必须 `public override`**：publicize 之后，`PackedIconPath`/`CanonicalVars`/`ExtraHoverTips` 这类成员写成非 public 会编译不过或失效。
4. **设置 UI 的自动保存**：RitsuLib 设置页在关闭/防抖时会对脏绑定调 `Save()`，所以「只允许点按钮保存」必须通过把 `Save()` 变成空操作来实现，不能靠不写代码。
5. **不要直接改 `ModDataStore` 返回的实例**：`Get<T>()` 返回的是存储内部同一对象，就地修改相当于「随时可能被落盘」。所以「即时生效」方案（v1.0.1）被撤销，恢复「暂存 + 丢弃」。
6. **图集帧 vs 单张 png**：`AtlasTexture` 带 region/margin/padding 元数据，直接指向解包的 png 会让图鉴光效渲染弱于原版；复用官方帧 + 渲染层镜像才与稀有版一致。
7. **文案 token 不会编译报错**：`{Stars:starIcons()}` 写成 `starsIcons` 只会让游戏内显示异常，改文案后必须逐条进游戏核对。
8. **清单与实现要一起改**：`DarvAllPossibleOptions` 若与生成器不同步，图鉴「先古 → 达弗」子分类与控制台补全就会漏项。
