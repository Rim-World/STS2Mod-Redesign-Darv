## 实装更改概括

- 新增 `RelicOptionCompat` 反射垫片，统一 107 / 111 的三参 `RelicOption` 与 113 的两参 `RelicOption`。
- 5 处 `darv.RelicOption(...)` 调用全部改走垫片。
- `DarvAllPossibleOptionsPatcher` 用 `.ToList()` 在 Prefix 内物化迭代器，异常可被 catch 并回退原版。
- `NRelicMirrorPatcher` 改为 `NRelic._Ready` + `NRelic.Reload` 双入口，并捕获 Model 未赋值的 `InvalidOperationException`。
- `RelicCollectionOutlinePatcher` 读取 Model 前增加同样的安全处理。
- 版本号升至 `1.0.1`；`build.ps1` 新增可选 `-Sts2DataDir`，用于三版本编译验证。
- 玩法、选项池、设置、本地化和 pck 资源均未改动。

## 简略技术细节

- 根因：v0.113 删除 `AncientEventModel.RelicOption(RelicModel, string, string)`，只保留两参重载；v1.0.0 的 DLL 在 JIT 时抛 `MissingMethodException`。
- 异常路径：`Darv.AllPossibleOptions` 的 Prefix 只返回迭代器，异常在 `NRelicCollection.LoadRelics` 枚举时才发生，绕过 Prefix 的 try/catch；`NRelicCollection.LoadRelics` 先把七个分类设为透明，异常后不再恢复，导致整页空白。
- 垫片：`RelicOptionCompat` 在运行时按参数类型查找三参或两参重载；三参存在时传 `("INITIAL", null)`，两参存在时传 `"INITIAL"`。
- 镜像：保留 `NRelic._Ready` 入口，并增加 `NRelic.Reload`（`_Ready` 与 `Model` setter 都会调用）；`TryGetModel` 捕获未赋值异常，后续 setter 再触发 `Reload` 时补上镜像。
- 构建：最终 DLL 使用 v0.111 的公开化 `sts2.dll` 编译；107 / 111 / 113 三份引用均编译通过；安装后的 DLL 用 Mono.Cecil 扫描 v0.113 成员，`TOTAL=0 UNIQUE=0`。
- 反射验证：独立 net9 测试分别加载 107 / 111 / 113 `sts2.dll` 与对应 RitsuLib Runtime；107/111 命中三参 `RelicOption`，113 命中两参；`NRelic._Ready` 与 `NRelic.Reload` 三版本均解析成功。
- 验证限制：未启动游戏，图鉴、Loadout、图标镜像与光效的实机效果未实测。

## 失败经验或实验教训

1. **迭代器补丁的 try/catch 边界**：`Prefix` 返回 `IEnumerable` 时，方法体不会立即执行；必须在 Prefix 内 `.ToList()` 或改成急切返回，否则异常仍在 UI 枚举时逃出。
2. **可选参数是编译期绑定**：`RelicOption(relic)` 在 111 编译后写死三参调用，运行时不会因为 113 只剩两参而自动改绑；跨版本调用必须走反射或运行时补丁。
3. **`NRelic.Model` 的 getter 不是可空查询**：113 在未赋值时抛异常，不能写 `n.Model == null`；应先捕获或改用生命周期钩子。
4. **外观补丁也应挂在稳定生命周期**：`_Ready` 早于/晚于 Model 赋值都可能发生；`Reload` 同时覆盖两条路径。
