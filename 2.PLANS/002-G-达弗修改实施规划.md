# 002-G 达弗修改实施规划（v1.0）

> 状态：规划 v1.0（2026-08-23）。前置决策见 `../1.ADR/001-达弗修改范围路线与双版本决策.md`。本规划在用户圈定塔1遗物清单后进入实现阶段（当前不写代码）。

## 1. 目标

开发一个《杀戮尖塔2》mod，**重构先古之民"达弗（Darv）"事件的选项池与概率**：
- 自定义遗物池（在塔2 现有遗物基础上增删，可能引入塔1遗物——待圈定）；
- 自定义权重与按幕/条件过滤（替换原版"均匀随机"）；
- 自定义 DustyTome 掺入策略；
- **default 107 与 beta 111 上行为完全一致（统一覆盖）**；
- 技术路线：**ritsulib 为主**（工作坊 0.5.14，含 0.107.1/0.111.0 变体）。

### 2.2 核心：达弗选项生成重构

原版逻辑（`Darv.GenerateInitialOptions`，两版方法体一致）：9/11 个 `ValidRelicSet{filter, relics}` → 逐集合均匀抽 1 候选 → 洗牌 → 50% 取 2+DustyTome / 50% 取 3。

**mod 方案（Prefix 整体替换，统一覆盖）**：

```
[PatchTarget(typeof(Darv), nameof(Darv.GenerateInitialOptions))]  // ritsulib IPatchMethod 声明
Prefix:
  1. 读 mod 配置的选项池定义（自定义数据结构，见 §2.3）
  2. 按当前 Owner/RunState 过滤 + 按配置权重（WeightedNextItem 或 ritsulib WeightedList 模式）抽取候选
  3. 按配置的 DustyTome 策略处理（原版 50% 或自定义概率/移除）
  4. 构造 EventOption 列表返回（__result），跳过原方法（return false）
同步处理：
  - AllPossibleOptions（Prefix 替换返回值）——保证图鉴/UI 一致
  - 选项数量：默认保持 3 个（AncientEventModel.GenerateInitialOptionsWrapper 是 sealed 收尾，不约束数量；但 UI 布局为 3 选项设计，超 3 需验证，见风险 R2）
```

复用点：`AncientEventModel.RelicOption(relic, ...)`（protected，含 RelicCmd.Obtain + Done 完整流程）→ 自建选项仍走官方完成路径；`EventOption.FromRelic` 可构造带自定义文本的选项。

### 2.3 选项池配置模型（核心数据结构，独立于游戏版本）

```
DarvPoolConfig（可存为 JSON，ritsulib ModDataStore 持久化 + 设置页编辑）：
  entries: [
    { relic: RelicModel 引用（按 ID 解析，运行时懒绑定）, 
      weight: float（默认 1，0 = 禁用该遗物）,
      minActIndex / maxActIndex（默认全部幕）,
      condition: 可选自定义条件（如牌组构成/角色）——v1 预留接口 }
  ]
  dustyTome: { enabled: bool, chance: float（默认 0.5）, replaceCandidateCount: int（默认 2） }
  optionCount: 3（默认；候选数 < 所需时按可用候选截断）
  # 兼容原版 9/11 集合的"分组互斥"语义：v1 用 weight 表达即可（组内互斥可用"同组标记"扩展，预留）
```

设计要点：
- **遗物按 ID 引用 + 运行期懒解析**：107/111 均有的遗物用同一 ID 解析；避免版本差异（两版达弗 12 候选 ID 一致）。
- **权重模型**：每遗物独立权重 → 抽 N 个不重复候选（不放回抽样）；支持"常见/罕见/禁用"。
- **统一覆盖语义**：两版都用 mod 配置生成选项，不读原版 `_validRelicSets`；原版 107 的"Ectoplasm+Sozu 同集合互斥"等结构差异自动消失。
- **DustyTome 策略**：可保留原版 50% 掺入（默认），或自定义概率/完全移除；掺入时先 `SetupForPlayer(Owner)`。

## 3. 双版本兼容策略（统一覆盖）

| 项 | 策略 |
|---|---|
| 池/概率 | mod 自定义，两版一致（不读原版静态池） |
| patch 目标 | `Darv.GenerateInitialOptions` / `AllPossibleOptions`：两版签名一致（已比对，仅 static ctor 不同），**同一份代码无 #if 分支** |
| 运行门槛 | manifest `min_game_version: "0.107.0"`；依赖 `{"id":"STS2-RitsuLib"}`（工作坊 0.5.14 两版变体齐备） |
| 防御 | DarvGuard 懒评估：`ModelDb.AncientEvent<Darv>()` 存在性 + ritsulib `Sts2HostVersion` 版本探测；未来版本若移除/改签名 → 告警并降级为原版行为 |
| 构建验证 | 用 107 与 111 两套反编译产物核对编译（dotnet 编译期引用游戏当前 dll=111；切 107 分支时重编译验证） |

## 6. 风险与开放问题

- **R1 塔1遗物清单未定**：不阻塞架构（配置驱动），阻塞 M4。→ 用户圈定。
- **R2 选项数量 >3**：Ancient 事件 UI 布局以 3 选项设计（ancient_event_layout.tscn），超 3 需验证或维持 3。
- **R3 ritsulib 版本跟进**：游戏更新后 ritsulib 需更新（工作坊自动）；manifest 依赖版本与实际编译版本需对齐（模板 checklist）。
- **R4 选项生成时机**：`GenerateInitialOptions` 在 `BeginEvent` 后调用，Owner/Rng 已就绪；Prefix 中可安全访问 Owner/RunState（与守卫配合，勿在 ModLoaded 阶段触碰 ModelDb）。
- **R5 多人模式**：Ancient 事件不可共享（EventRoom 注释），选项按玩家各自生成；Prefix 需保持无状态/确定性（用事件自己的 Rng 或 mod RNG 流）。
- **R6 AllPossibleOptions 一致性**：漏改会导致图鉴/统计与实测不符；两处必须同时 patch。
- **开放问题**：选项是否保留"3 选 1"；DustyTome 默认概率；权重默认值（是否先复刻原版各幕分布作为基线，再叠加用户调整）。
