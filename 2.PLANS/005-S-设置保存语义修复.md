## v2：设置暂存残留修正 + 设置页顶部提示（2026-08-24）

### 问题
玩家改开关但不点"保存并重启"：
- 自行重启游戏 → 按钮显示亮的（正确，未落盘）；
- **不重启游戏**，退出设置界面再重新进入 → 按钮显示关掉的（暂存值残留）——而实际生效仍是磁盘值（亮的），UI 与生效状态不一致。

### 根因
ritsulib 页面内容缓存池化（`RetainedPageContentCacheLimit=2`、idle 5s 释放）跨打开复用控件；`DeferredSaveBinding.Read()` 返回"暂存 ?? 磁盘"，缓存复用刷新回调显示暂存值；v1 没有打开/关闭钩子重置。

### 方案
新增 `Patches/SettingsPendingResetPatcher.cs`（IsCritical=false，注册于 cosmeticPatcher），Prefix hook `RitsuModSettingsSubmenu.OnSubmenuOpened` + `OnSubmenuClosed`，调用 `DarvSettingsUi.ResetPendingBindings()`：
- `OnSubmenuOpened` Prefix：在 `EnsureUiUpToDate` 刷新控件**之前**清空全部 `_pending` → 刷新回调 `Read()`=磁盘值 → 重开设置页显示修改前状态
- `OnSubmenuClosed` Prefix：退出设置界面兜底清空
- 刻意**不** hook `OnSubmenuHidden/OnSubmenuShown`：隐藏→重显路径无内容刷新点，清了会导致控件显示与 `Read()` 不一致（更糟）
- 落盘语义不变：只有"保存并退出"按钮写盘

设置页最前新增"保存须知"section（`section.top.title`/`section.top.notice`，三语）："需要点击本页面最下方的「保存并退出」按钮才能保存设置，否则设置将不会保存。"

### 验证
- 构建 0 错误；dll 47616 字节（18:21:30）/ pck 58660 字节（18:21:50），已安装 `C:\Game\Steam\...\mods\DarvRelicPoolMod\`。
- 测试用例：见 `../3.DOCS/010-T-手动测试方案.md` §3.6（v2：退出设置界面后重进显示修改前状态）。

## v1：DeferredSaveBinding 保存语义（原记录）

### 背景

设计约定（ADR-001/002）"设置只有点'保存并退出'才落盘"。实测发现 ritsulib 设置 UI 的脏绑定防抖自动保存（`FlushDirtyBindings`，0.35s，RitsuModSettingsSubmenu.cs:3297-3322）会对所有脏绑定调用 `Save()`，导致**退出设置界面即落盘**，与约定相悖。

### 方案

1. 新增 `DeferredSaveBinding.cs`（`IStructuredModSettingsValueBinding<bool>` + `IDefaultModSettingsValueBinding<bool>`）：
   - `Read()` = 本会话暂存值 ?? 磁盘值（保证 UI 刷新回调不弹回）
   - `Write()` = 仅写内存暂存（`_pending`）
   - `Save()` = 空操作（阻断 UI 自动保存路径）
2. `DarvSettingsUi.cs` 重写：6 个开关全部改用 DeferredSaveBinding；"保存并退出"按钮为**唯一落盘途径**——以磁盘值为基础、用 `PendingValue` 覆盖改动项 → `store.Save` → 清暂存 → `NGame.Quit()`。
3. 三语 settings.json 新增提示文案："请点击最下面的保存按钮，退出游戏后重启才能应用设置，否则设置将不会保存。"

### 已知语义边界（v2 已解决）

- v1：同一游戏运行内"未保存关闭设置页 → 重开"时暂存值仍挂在 UI（页面缓存复用）；落盘仍只发生在点按钮时。→ **v2 已修复**：退出设置界面时清空暂存，重开显示修改前状态。
- 落盘语义始终不变：只有点"保存并退出"才写盘。

- 测试用例：见 `../3.DOCS/010-T-手动测试方案.md` §3.6（保存语义）。
