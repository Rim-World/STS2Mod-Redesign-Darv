## ② "退出设置界面即保存"回归——根因追溯与修复规划

### 现象
v1.0.1（修复记录 8）起：改开关 → 不点"保存并退出" → 退出设置界面 → 重进，开关仍显示改动值 → 用户判定"没点保存却被保存了"，与设计（只有保存并退出才保存）相悖。

### 根因（已追溯，证据链完整）
1. **没有真正的"落盘"回归**（settings.json 未被写）：
   - `DeferredSaveBinding.Save()` 仍是空操作；
   - `FlushDirtyBindings`（OnSubmenuClosed/OnSubmenuHidden/0.35s 防抖）只对脏绑定调 `binding.Save()`——`ModSettingsBindingFlushPlanner.SelectEffectiveSaveRoots` 返回的就是我们的绑定（我们不实现 `IModSettingsBindingSaveDispatch`，不做覆盖合并），Save 空 → 不落盘；
   - `ModDataStore.SaveAll()` 在 ritsulib 源码中**无任何调用者**。
2. **真正的回归原因**：v1.0.1 把 `Write` 从"仅内存暂存 `_pending`"改为"直接写入 `DarvSettings.Current`（live 内存态）"，并**停用了 `SettingsPendingResetPatcher`**（它负责在打开/关闭设置界面时清暂存）→ 未保存的改动在退出设置界面后**保留在内存态**，重进设置界面 `Read()` 读 live → 显示改动值。现象与修复记录 4/5 修复前完全一致（用户视角的"被保存了"），即**上一轮"live 即时生效且保留"的设计过度**。
3. **附带结构性隐患（v1.0.1 引入）**：`ModDataStore.Get<T>` 返回 **store 内部持有的同一实时实例**（`RegisteredDataEntry.Data`，ModDataStore.cs:467），v1.0.1 的 `Write` 直接改它就是改 store 内部对象——当前虽无自动 Save 路径，但任何未来/第三方触发 `store.Save`（云同步、互操作 API、其他 mod）都会把未保存改动落盘。必须消除。

### 修复规划（恢复到"暂存+丢弃"，保留"无快照"）
1. **`DeferredSaveBinding`**：恢复 `_pending`；`Write` 只写 `_pending`（**不碰** store 实例）；`Read` = `_pending ?? 磁盘值`（`_getter(DarvSettings.Load())`，只读）；`Save` 空操作；恢复 `PendingValue` / `ClearPending`。
2. **`DarvSettings`**：保持无快照（`Current => Load()`；`Load()` 返回 store 内部实例但只读；删除/保留 `_live` 均可——建议直接 `Load()`，不再缓存可变实例）。
3. **`SettingsPendingResetPatcher`**：**重新注册**（OnSubmenuOpened/Closed Prefix 清 `_pending`）→ 退出设置界面即丢弃未保存改动，重进显示原值（修复记录 5 语义恢复）。
4. **`SaveAndQuit`**：恢复"以磁盘为基础 + `PendingValue` 覆盖 → `store.Save` → `ClearPending` → `NGame.Quit()`"。
5. **`ModEntry`**：恢复 `RegisterPatch<SettingsPendingResetPatcher>()`；快照订阅保持删除（无快照）。
6. **文案调整（三语）**：行为回到"未保存不生效、不保留；只有保存并退出才落盘"。当前文案"设置对当前对局立刻生效 / 修改将在本对局立刻生效"不再准确，建议改为：
   - zhs：per_character.description → "…未保存的改动不会生效；点击本页最下方「保存并退出游戏」后设置才会保存，重启游戏后立即生效。"；button.saveAndQuit.description → "保存你的设置并自动退出游戏。修改将在重启游戏后立即生效。"
   - eng/zht 对应翻译（保留用户已改的 "the"）。
   - （措辞最终以用户确认为准）
7. **版本**：建议 bump 1.0.1（行为修正；上轮行为变更未 bump）。

### 修复后完整行为（预期）
| 操作 | 结果 |
|---|---|
| 改开关（UI 暂存） | 达弗选项**不变**（按磁盘值）；开关显示改动值（不弹回） |
| 退出设置界面（未点保存） | 改动**丢弃**；重进显示原值 |
| 直接重启（未点保存） | 磁盘未变 → 原值 |
| 点"保存并退出" | 落盘 + 退出游戏 → 重启后**立即生效**（主菜单控制台/新局均按新值，无快照） |

## ③ 蛇眼开关：五个职业按钮并排一行（规划）

### 现状
`DarvSettingsUi` 蛇眼 section 用 5 个 `AddToggle`（每个开关独立一行）。

### ritsulib 能力（已核实）
- `ModSettingsSectionBuilder.AddCustom(id, label, Func<IModSettingsUiActionHost, Control> controlFactory, description)`（ModSettingsBuilders.cs:1225）——控件工厂返回任意 `Control` 作为**整行内容**（`CreateCustomEntry` 直接返回工厂结果，Entries.cs:843-846）。
- `IModSettingsUiActionHost` 提供 `RequestRefresh()` 与 `MarkDirty(binding)`（ModSettingsUiActions.cs:14）——自定义控件可走标准脏标记流程（我们的 `Save()` 空操作保证不落盘）。
- 自定义条目**没有自动刷新回调**（CreateCustomEntry 不注册 RegisterRefreshWhenAlive）→ 按钮视觉由我们自己维护（点击即更新），不依赖 ritsulib 刷新。

### 方案
1. 蛇眼 section 的 5 个 `AddToggle` 替换为 **1 个 `AddCustom`**：
   - `controlFactory` 构建 `HBoxContainer`（水平、`ExpandFill`、等分宽度、行高对齐），内含 5 个 Godot `Button`，各显示职业名（`T("character.ironclad/silent/defect/regent/necrobinder")`）。
   - 每个按钮对应一个 `DeferredSaveBinding`：点击 → `binding.Write(!当前值)`（仅暂存 `_pending`，不落盘）→ `host.MarkDirty(binding)` → 按钮视觉立即切换（`ToggleMode` 按下态/高亮）。
   - 初始/重进视觉：创建控件时按 `binding.Read()`（`_pending ?? 磁盘`）初始化按钮状态——与保存语义完全兼容（未保存退出设置界面 → patcher 清 `_pending` → 重进重建控件 → 显示原值）。
2. section 标题与描述保留（说明默认开启、储君不适配理由等）；按钮行 label 参数可传空或复用 section 说明。
3. 视觉：先用 Godot `Button` 默认样式（`ToggleMode` + 按下态），构建后由用户在游戏内确认观感；若不搭 ritsulib 主题，备选方案为复用 ritsulib 的 `ModSettingsToggleControl` 并排（需确认其构造与样式公开性）。
4. 兼容性：`AddCustom` 是 ritsulib 0.5.14 API，与游戏 107/111 分支无关（ritsulib 自身按版本提供），无双版本问题。
