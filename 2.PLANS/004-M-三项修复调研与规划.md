## 问题①：图鉴中角色专属遗物的背景色光效（我们的 6 件新遗物不发光）

### 现象
- 官方角色专属遗物在图鉴中 outline 冒角色背景色光（铁甲=红、静默=绿、故障=蓝、储君=橙、亡灵=粉）；战斗中不冒光。
- 我们的 6 件塔1 遗物在图鉴中不冒光（用户已确认光效非素材自带）。

### 根因（完整机制链）
1. **颜色定义**：`RelicPoolModel.LabOutlineColor`（默认 `StsColors.halfTransparentBlack`，`RelicPoolModel.cs:18`）；各角色池 override：IroncladRelicPool=red（`IroncladRelicPool.cs:15`）、SilentRelicPool=green、DefectRelicPool=blue、RegentRelicPool=orange、NecrobinderRelicPool=pink。
2. **图鉴消费点**：`NRelicCollectionEntry._Ready`（`NRelicCollectionEntry.cs:150-160`）——遍历 `ModelDb.AllCharacterRelicPools`（=`AllCharacters.Select(c => c.RelicPool)`，`ModelDb.cs:239`），若遗物 Id 属于某角色池 → `nRelic.Outline.SelfModulate = 该池.LabOutlineColor（alpha 置 0.66）`。
3. **战斗中不冒光**：战斗/遗物栏用 `NRelicInventoryHolder`（无 LabOutlineColor 逻辑）——与用户观察一致。
4. **我们的遗物为何不冒光**：注册在自定义 `DarvModRelicPool`（非角色池）→ 不属于任何 `AllCharacterRelicPools` → 保持默认色。

### 为什么不能把遗物加进官方角色池（排除项）
`RelicGrabBag` 开局从 `SharedRelicPool + player.Character.RelicPool` 装袋（`RelicGrabBag.cs:75-76`）——若 6 件加入角色池，它们会进入精英/商店/宝箱随机掉落，违背 ADR-002 决策（"只在达弗出现"）。

### 修复方案（推荐）
**patch `NRelicCollectionEntry._Ready`（Harmony Postfix）**：渲染完成后，若 `_relicNode is NRelic n` 且 `n.Model` 为 mod 遗物（按 Id 前缀 `DARV_RELIC_POOL_MOD_RELIC_` 识别），按角色映射设置 `n.Outline.SelfModulate`：
- 符文立方体 / 痛楚印记 → `StsColors.red`（alpha 0.66，与官方一致）
- 悬浮风筝 / 袖剑 → `StsColors.green`
- 核能电池 / 机械臂 → `StsColors.blue`
- `NRelic.Outline`/`NRelic.Model` 均为 public（`NRelic.cs:83,85`）；`_relicNode` 为 private（publicize 后可访问）。
- 备选（更贴近官方路径）：Prefix 修改遍历逻辑，在官方匹配后追加 mod 映射——实现更绕，不推荐。

## 问题②：图鉴中 6 件新遗物按角色分组连排

### 根因
图鉴"先古"分类的 Ancient 分支（`NRelicCollectionCategory.LoadRelics`，`NRelicCollectionCategory.cs:174-204`）：达弗子分类的遗物 = `AllPossibleOptions` 提取后 **`OrderBy(r => r.Title.GetFormattedText(), LocManager.StringComparer)`**（:194-196）——按标题排序，无法体现自定义顺序。

### 修复方案
patch `NRelicCollectionCategory.LoadRelics`（public，`NRelicCollectionCategory.cs:148`），仅 Ancient 分支生效：
- **方案 A（Transpiler，推荐）**：把 Ancient 分支的 `OrderBy(Title)` 替换为自定义排序调用——mod 6 件按固定顺序（符文立方体→痛楚印记→悬浮风筝→袖剑→核能电池→机械臂）连续排在首位（或末位，见待确认），其余（官方 12 件 + 储君/亡灵 6 rare）保持原标题序。用 ritsulib `HarmonyIlRewriter` 实现（模式匹配 OrderBy 调用点，替换为静态排序方法）。
- **方案 B（Postfix 重排，简单）**：`LoadRelics` Postfix 后遍历达弗子分类的 `_relicsContainer` 子节点（`NRelicCollectionEntry`，其 `relic` 为 public 字段 `NRelicCollectionEntry.cs:93`），按映射顺序 `MoveChild` 重排。实现简单，但依赖渲染完成后的节点顺序（标题排序已在 LoadSubcategory 内完成，Postfix 时节点已存在，重排可行）。
- 实现时优先方案 A（不依赖 UI 结构、无闪烁），若 Transpiler 匹配困难退方案 B。

## 问题③：加费遗物描述的能量符号显示为 `{Energy:energyIcons()}` 原文

### 根因
- 描述中的 `{Energy:energyIcons()}` 是 SmartFormat 格式化表达式，需要 `DynamicVars` 中存在名为 **"Energy"** 的 `EnergyVar`（`EnergyVar.cs`：默认名 "Energy"，`EnergyVar(int energy)`）。
- 官方 +1 能量遗物通过 `CanonicalVars` 注册 EnergyVar：如 `PhilosophersStone.CanonicalVars => [new PowerVar<StrengthPower>(1m), new EnergyVar(1)]`（`PhilosophersStone.cs:20-24`），`DynamicEventDescription`（`RelicModel.cs:79-89`）把 DynamicVars 注入描述后 SmartFormat 才能渲染能量图标。
- **我们的痛楚印记/悬浮风筝未定义 CanonicalVars** → 描述中 `{Energy:energyIcons()}` 因缺变量原样输出（SmartFormat 缺失变量保留原文）。

### 修复方案（低风险，直接改代码）
- `MarkOfPain`（痛楚印记）与 `HoveringKite`（悬浮风筝）添加：
  ```csharp
  protected override IEnumerable<DynamicVar> CanonicalVars => [new EnergyVar(1)];
  protected override IEnumerable<IHoverTip> ExtraHoverTips => HoverTipFactory.ForEnergy(this); // 悬停提示能量图标，与官方一致
  ```
  using：`MegaCrit.Sts2.Core.Localization.DynamicVars`、`MegaCrit.Sts2.Core.HoverTips`。
- 其余 4 件描述无动态变量（符文立方体"抽1张"/袖剑"4伤害"/核能电池"1等离子"/机械臂"每2回合1栏位"）——无需改动。
