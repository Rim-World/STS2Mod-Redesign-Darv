## 一、任务拆解（6 个子任务）

1. **素材**：6 张图标左右翻转（+ 6 张 outline 翻转，图鉴光效用）
2. **6 个遗物类**：效果实现（照官方模板改参数）
3. **注册与文案**：DarvModRelicPool 注册 + 三语命名（先古/Ancient 前缀）
4. **达弗池逻辑**：储君/亡灵 20% 池改为"三件先古均等随机（排除已持有稀有版的对应件）"
5. **稀有版互斥**：获得先古版 → 对应稀有版从宝箱/商店/精英/事件永久移除（本局）
6. **图鉴**：光效（储君橙/亡灵粉）+ 排序（铁甲→静默→储君→亡灵→故障）

## 二、技术路线与官方参考（全部已验证）

### 1. 素材（左右翻转）
- 源素材：`pics/素材/塔2-遗物/` 有 6 件稀有遗物 png + outline（lunar_pastry / mini_regent / orange_dough / bookmark / big_hat / ivory_tile，含 _outline）。
- 做法：一次性生成水平翻转图（PowerShell System.Drawing 翻转，构建脚本外处理），放入工程 `DarvRelicPoolMod/images/relics/`，命名 `ancient_lunar_pastry.png` 等 + outline 同步翻转。
- 坑：尺寸/透明通道保持原样（System.Drawing 可保留）；与现有 12 张塔1素材同目录、随 pck 打包。

### 2. 六个遗物类（Relics/ 下 6 个新文件，全部照官方模板改参数）
| 新遗物 | 官方模板 | 改动点 | 关键 API |
|---|---|---|---|
| AncientLunarPastry 先古月亮糕点 | LunarPastry（回合结束+1星） | 回合**开始**（AfterSideTurnStart）+ **2** 星 | `PlayerCmd.GainStars`、`StarsVar(2)` |
| AncientMiniRegent 先古迷你储君 | MiniRegent（消耗星辉+1力/每回合一次） | **获得与消耗**星辉各 +1 力（每回合各一次，两个独立标记） | `AfterStarsSpent`、`AfterStarsGained`、`PowerCmd.Apply<StrengthPower>`、`PowerVar<StrengthPower>(1m)` |
| AncientOrangeDough 先古橙色团块 | OrangeDough（战斗开始 2 张随机无色牌） | **3** 张 + **升级** | `ModelDb.CardPool<ColorlessCardPool>`、`CardFactory.GetDistinctForCombat`、`CardCmd.Upgrade`、`CardPileCmd.AddGeneratedCardsToCombat(Hand)`、`CardsVar(3)` |
| AncientBookmark 先古书签 | Bookmark（回合结束随机保留牌耗能-1直到打出） | 减费改为**本场战斗永久** | `AfterFlush`（retainedCards）、`Rng.CombatCardSelection.NextItem`、**`EnergyCost.AddThisCombat(-1, reduceOnly: true)`** |
| AncientBigHat 先古大帽子 | BigHat（战斗开始 2 张随机虚无牌） | **3** 张 + **升级** | 角色卡池 `Keywords.Contains(CardKeyword.Ethereal)` 筛选 + 同上 |
| AncientIvoryTile 先古象牙麻将牌 | IvoryTile（打出实际耗能≥3 回 1 费） | 阈值 **3→2** | `AfterCardPlayed`、`cardPlay.Resources.EnergyValue`、`PlayerCmd.GainEnergy`、`EnergyVar(1)`+`EnergyVar("EnergyThreshold",2)` |

**已验证的机制**：
- 星辉：`PlayerCmd.GainStars(decimal, Player)`（LunarPastry 用）；`AfterStarsGained(int, Player)` hook 存在（AbstractModel.cs:1186）；`StarsVar`（默认名 "Stars"）。
- 战斗内永久减费：`CardEnergyCost.AddThisCombat(int, bool reduceOnly=false)`（CardEnergyCost.cs:319）——正是"本场战斗耗能-1"（官方 LocalCostModifierExpiration.WholeCombat 语义）。
- 升级：`CardCmd.Upgrade(CardModel, CardPreviewStyle)`（官方注释推荐从模型调用用 CardCmd.Upgrade）。
- 保留/虚无：`AfterFlush`（官方 Bookmark 同点）、`CardKeyword.Ethereal/Retain` 筛选。
- 双版本：六件官方稀有遗物 **107 全存在**；全部 hook（AfterSideTurnStart/End、AfterStarsSpent/Gained、AfterFlush、AfterCardPlayed、BeforeSideTurnStart）107/111 **签名一致**；`RelicGrabBag.Remove` 与 `Player.RelicGrabBag` 107 也存在。实现时需再核对 `AddThisCombat` 与 `CardCmd.Upgrade` 的 107 签名（大概率一致）。

### 3. 注册与文案
- `[RegisterRelic(typeof(DarvModRelicPool))]` + `RelicRarity.Ancient`（不进 RelicGrabBag → 只达弗出现）。
- ID 前缀沿用 `DARV_RELIC_POOL_MOD_RELIC_`（图鉴光效/排序 patch 的 `IsModRelic` 检查自动通过）。
- 三语 relics.json：zhs/zht 前加"先古"、eng 前加 "Ancient"；描述含星辉/能量图标（星辉写法推测 `{Stars:starsIcons()}`——**需游戏内确认**，与既有 `{Energy:energyIcons()}` 同体系）。

### 4. 达弗池逻辑（DarvOptionPool）
- `BuildCharacterPool` 储君/亡灵分支：改为三件先古池 = **排除"已持有稀有版"对应的先古件**（HasRelic 检查，沿用现有 `HasRelic`），`rng.NextItem` 均等随机（各 ≈6.67%）。
- 三件稀有全持有 → 池空 → 沿用现有**归一化**（魔典 62.5% / 金字塔 37.5%）。
- **废除现有 BuildProgressivePool 递进逻辑**（用户：不再有优先顺序）。
- 另一方向互斥：持有稀有版 → 达弗不出先古版 ✓（池构建时排除）。
- 未知角色/职业关闭回退原版逻辑不变。

### 5. 稀有版互斥（官方机制，一行代码）
- 塔2 宝箱/商店/精英掉落/事件遗物全部从玩家 `RelicGrabBag` 抽取（**不放回**：抽到即从桶移除，本局不再出现——这就是用户说的"现成防重复机制"）。
- 我们的先古遗物 override **`RelicModel.AfterObtained()`**（RelicModel.cs:546，获得钩子）：`Owner.RelicGrabBag.Remove(ModelDb.Relic<LunarPastry>())`（等 6 组映射）→ 获得先古版后，对应稀有版本局不再从任何 grab-bag 来源出现。官方 `Remove` API 注释即"removed from the bucket so that it is never rolled"。
- 坑：grab bag 在 `Player.RelicGrabBag`（public）；先古遗物只经达弗获得（Ancient 不进 bag）→ 获得时机确定；联机各玩家独立 bag（按 owner 处理 ✓）。

### 6. 图鉴
- **光效**：`RelicCollectionOutlinePatcher.GetOutlineColor` 扩展 6 件映射——储君 3 件 → `StsColors.orange`（FFA518）、亡灵 3 件 → `StsColors.pink`（FF78A0）（官方角色池配色，alpha 0.66 沿用）；对局/战斗无光效 ✓（现有 patch 只挂图鉴 `_Ready`）。
- **排序**：`RelicCollectionSortPatcher` 扩展顺序。建议整体顺序 **铁甲2 → 静默2 → 储君3 → 亡灵3 → 故障2**（13 件一组连续排列，与用户给的职业顺序一致）——待确认。
- 稀有度 Ancient → 自动进"先古→达弗"栏 ✓。

## 三、坑与风险清单

1. **星辉图标文案**：`{Stars:starsIcons()}` 为推测写法，需游戏内确认（或先看官方 LunarPastry 英文描述确认图标 token）。
2. **升级 API**：`CardCmd.Upgrade` 需要 `CardPreviewStyle` 参数（实现时看默认值/重载）；升级对不可升级牌是否安全需 try/catch 或过滤。
3. **先古书签"被保留的牌"**：官方 Bookmark 过滤 `非X费 && 当前耗能>0`；用户文案字面无过滤——建议保留官方过滤（0 费牌减费无意义）——待确认。
4. **先古象牙麻将牌阈值**：官方用 `cardPlay.Resources.EnergyValue`（**实际支付**能量，含减费效果）；用户"耗能>=2"按实际支付理解——建议与官方一致——待确认。
5. **先古月亮糕点每回合 +2 星**：储君星辉是否有上限/溢出；与先古迷你储君联动（回合开始 +2 星也会触发"获得星辉+1力"）——组合测试点。
6. **先古迷你储君"每回合第一次获得/消耗"**：两个独立标记；获得星辉的判定是否排除"非玩家来源"（如月亮糕点先于迷你储君执行顺序）——实现细节测试。
7. **AddThisCombat / CardCmd.Upgrade 的 107 签名**：实现时核对。
8. **素材翻转**：System.Drawing 翻转注意透明通道；12 张（6 png + 6 outline）。
9. **达弗先古池空池归一化**：沿用 62.5/37.5（与现有储君递进空池逻辑一致）。
10. **图鉴排序与互换联动**：现有 Swap 联动（痛楚印记↔核能电池组内互换）与新顺序合并时保持正确。
