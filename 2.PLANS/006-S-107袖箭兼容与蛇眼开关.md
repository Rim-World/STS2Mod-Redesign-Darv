## ① 107 版本袖箭加伤失效——根因与修复方案

### 根因（已定位，证据链完整）

塔2 的伤害修正虚方法 `AbstractModel.ModifyDamageAdditive` 在两个版本**签名不同**：

| 版本 | 签名 | 证据 |
|---|---|---|
| default 107 | `(Creature? target, decimal amount, ValueProp props, Creature? dealer, CardModel? cardSource)` 5 参 | decompiled-107/.../AbstractModel.cs:1552；调用点 Hook.cs:2519 |
| beta 111 | `(..., CardModel? cardSource, CardPlay? cardPlay)` 6 参 | decompiled-111/.../AbstractModel.cs:1579；调用点 Hook.cs:2528 |

官方自己的 `StrikeDummy`（同类加伤遗物）在 107/111 各自按本版签名 override——**官方按版本编译**。我们的 mod 是单 dll（按 111 编译），WristBlade 按 111 的 6 参签名写 `public override`：

- 107 运行时，基类虚方法表只有 5 参槽位；我们的 6 参 override **不占任何虚槽 → 永不调用、静默失效**（不崩溃、无报错，与用户实测"没有任何效果"完全吻合）。
- 111 运行时正常（6 参虚槽命中）。

**仅袖箭受影响**（与用户报告一致）：其余 5 件遗物用到的 hook 已逐一核对，107/111 签名完全一致——`AfterCurrentHpChanged`（107:552）、`ModifyMaxEnergy`（107:1738）、`BeforeCombatStart`（107:484）、`AfterCardDiscarded`（107:370）、`AfterSideTurnStart`（107:1243）、`BeforeSideTurnStart`（107:1222）、`AfterCombatEnd`（107:506）。WristBlade 判定所需 API（`IsPoweredAttack`、`CardModel.Type`/`CardType.Attack`（107 CardModel.cs:288）、`EnergyCost.CostsX`、`GetWithModifiers(CostModifiers.All)`（107 CardModel.cs:1582 官方同款用法））在 107 全部存在。

### 修复方案（双机制，版本自适应）

1. **111 路径保持现状**：WristBlade 现有 6 参 override 不动（官方标准写法）。
2. **107 路径新增 optional Harmony patch**：新增 `Patches/WristBlade107CompatPatcher.cs`：
   - `GetTargets()` → `PatchTarget.OptionalMethod<AbstractModel>("ModifyDamageAdditive", typeof(Creature), typeof(decimal), typeof(ValueProp), typeof(Creature), typeof(CardModel))`（显式 5 参类型 → 107 解析成功、111 找不到该方法自动忽略，`ignoreIfMissing` 保证 111 零副作用）
   - `Postfix(AbstractModel __instance, ref decimal __result, Creature? dealer, ValueProp props, CardModel? cardSource)`：仅当 `__instance is WristBlade` 且判定条件满足时 `__result += 4m`（守卫保证不影响其他模型的伤害）
   - 判定逻辑与现有 override 抽成 WristBlade 的公共静态方法（`ShouldGrantBonus`），两处共用，防止逻辑漂移
3. 注册到**必选 patcher**（与 DarvOptionsPatcher 同组，IsCritical=true）——107 下这是玩法关键路径；111 下被忽略不影响。

### ① 验证要点
- 107：获得袖箭 → 打 0 费攻击牌 → +4；X 费/1 费攻击/技能不触发；静默猎手 0 费攻击正常
- 111：回归不变（patch 被忽略，走原有 override）

## ② 新功能：5 角色"槽位2 是否出现异蛇之眼"开关

### 背景
用户发现储君卡池与蛇眼（异蛇之眼）不契合（其高费牌体现在星辉消耗而非单纯费用）。槽位2 = 添水/灵体外质/贤者之石/天鹅绒颈圈/异蛇之眼 五选一（各 20%）。

### 方案（与既有设置体系完全一致）
1. **DarvSettings** 加 5 个字段（默认全开 = 现状不变）：`SneckoIronclad/SneckoSilent/SneckoDefect/SneckoRegent/SneckoNecrobinder`（bool，默认 true）+ 辅助方法 `IsSneckoEnabledForCharacter(entry)`。旧 settings.json 缺字段自动用默认值（true），无迁移问题。
2. **DarvSettingsUi** 加 5 个 DeferredSaveBinding + 新 section（建议放"逐职业设置"与"交换设置"之间，标题如"异蛇之眼出现开关"），三语文案；"保存并退出"组装、ResetPendingBindings 清理同步纳入。
3. **DarvOptionPool.Generate** 槽位2：按角色查 `IsSneckoEnabledForCharacter`，关闭时从 Slot2Pool 剔除 SneckoEye → 剩余四件各 25%（等分归一化，与槽位均匀设计一致）。
4. 语义继承：
   - 开局快照（Current = Snapshot ?? Load）→ 运行中改设置不影响当前局 ✓
   - 职业关闭（回退原版）时蛇眼开关**不生效**（回退 = 完全原版逻辑）——与既有"关闭回退该版本原版"设计一致
   - 未知角色回退原版，开关不生效 ✓
   - 与已拥有无联动（官方达弗槽位2 不查已拥有，维持现状）✓
   - 保存逻辑：只有"保存并退出"落盘 + 退出设置界面丢弃未保存改动 ✓

### ② 验证要点
- 关闭某角色蛇眼 → 该角色达弗槽位2 只出四件（各 25%），永不出异蛇之眼；其他角色不受影响
- 默认全开时行为与现状完全一致
- 职业关闭 + 该职业蛇眼关闭同时存在 → 回退原版（蛇眼可出）
- 新局生效语义、保存语义同既有测试

## 实现记录（2026-08-24）
- `Relics/WristBlade.cs`：**不写 override**（107/111 签名不同，且 mod 直接引用游戏目录 sts2.dll 编译——切分支后本地 dll 换版，override 无法跨版本编译）；判定逻辑抽为 `ShouldGrantBonus(self, dealer, props, cardSource)` 公共静态方法
- 新增 `Patches/WristBladeCompatPatcher.cs`（IsCritical=true，注册于必选 patcher）：**双 optional patch 运行时自适应**——
  - 5 参 target（107）：`OptionalMethod<AbstractModel>("ModifyDamageAdditive", 5 参类型)` → 107 命中 / 111 忽略
  - 6 参 target（111）：`CardPlay` 类型用 `Type.GetType` 运行时探测（避免编译期依赖）——107 无此类型不注册 / 111 注册命中
  - Postfix 不声明 CardPlay 参数（Harmony 按名注入），`__instance is WristBlade` 守卫后 `__result += 4m`；两 target 共用
- `DarvSettings.cs`：`SneckoIronclad/SneckoSilent/SneckoDefect/SneckoRegent/SneckoNecrobinder`（默认 true）+ `IsSneckoEnabledForCharacter`
- `DarvSettingsUi.cs`：5 个 DeferredSaveBinding + "snecko" section（放逐职业设置与交换设置之间）；SaveAndQuit/ResetPendingBindings 同步纳入
- `DarvOptionPool.cs`：`BuildSlot2Pool` 按角色剔除 `SneckoEye`（关闭后四件各 25%）
- 三语 settings.json：`section.snecko.title/description` + `character.*`（5 职业名）
