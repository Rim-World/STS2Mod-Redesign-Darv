## 1. 用户设计全文（转述整理）

**三选项槽位（固定位置）**：
- **槽位 1**：星盘、潘多拉魔盒、黑星、召唤铃铛、空鸟笼——五选一，各 1/5（20%）。
- **槽位 2**：添水、灵体外质、贤者之石、天鹅绒颈圈、异蛇之眼——五选一，各 1/5（20%）。
- **槽位 3**：尘封魔典 **50%**（保留原版"按角色发放不同先古卡"机制）；符文金字塔 **30%**；**角色专属池 20%**（两件随机其一，各 10%）：
  - 铁甲战士：塔1 符文立方体、痛楚印记
  - 静默猎手：塔1 悬浮风筝、袖剑
  - 故障机器人：塔1 核能电池、机械臂
  - 储君：月亮糕点、迷你储君（初始池）→ 其一已拥有则加入橙色团块 → 其二已拥有则只剩最后一个 → **三者全拥有则 50:30 重新归一化（魔典 62.5%、符文金字塔 37.5%）**
  - 亡灵契约师：书签、象牙麻将牌（初始池）→ 其一已拥有则加入大帽子 → 同储君递进逻辑 → 三者全拥有同归一化

**设置界面（ritsulib）**：
- ① 5 职业分别开关（默认全开）；关闭某职业 → 该职业退回**该版本（107/111 各自）原版默认逻辑**；各职业独立保存互不影响。
- ② 保存后**自动退出游戏**（非重启），按钮文案提醒"保存时将自动退出"；修改对当前局不生效、新局生效。
- ③ "交换"开关（默认关）：铁甲战士池的痛楚印记 ↔ 故障机器人池的核能电池；开启后痛楚印记只在故障机器人出现、核能电池只在铁甲战士出现；附说明文案（理由：塔2 战士的状态牌体系被移植给了故障机器人）。
- ④ **联机说明条目**（单独列出，中英文）：联机时每个玩家都需安装本 mod；联机适用性未经测试；每个玩家的概率分布按玩家自己的设置生成。
- 说明文案中英文自动切换（zhs/zht → 中文，其余 → 英文）。

**其他**：mod 只支持中英文；6 件塔1 遗物效果**直接照搬塔1**；稀有度与图鉴见 §6。

## 3. 实现架构

### 3.1 模块总览

```
9.SRC/DarvRelicPoolMod/（Godot/C#，ritsuLib 依赖）
├── ModEntry.cs                    # [ModInitializer]：content pack + patcher + 设置页注册
├── DarvOptionsConfig.cs           # 设置模型（5 职业开关 / 交换开关），ModDataStore 持久化
├── DarvOptionsPatcher.cs          # ritsulib IPatchMethod：Prefix 替换 Darv.GenerateInitialOptions + AllPossibleOptions
├── DarvOptionPool.cs              # 新选项生成器（槽1/槽2/槽3 + 已拥有递进 + 归一化）
├── VanillaFallbackPool.cs         # 原版逻辑回退（职业关闭时；反射读 _validRelicSets 自适应版本）
├── Relics/                        # 6 件塔1 遗物（RunicCube/MarkOfPain/HoveringKite/WristBlade/NuclearBattery/Inserter，Rarity=Ancient）
├── localization/{eng,zhs,zht}/…  # 新遗物 + 设置文案
└── build.ps1 / manifest
```

### 3.2 选项生成（Prefix 替换，返回列表顺序 = UI 槽位顺序）

```
GenerateInitialOptions(Owner)：
  职业开关关 → 返回原版逻辑结果（VanillaFallbackPool，见 3.3）
  [槽1] = 五选一(星盘/潘多拉魔盒/黑星/召唤铃铛/空鸟笼)          # 各 20%
  [槽2] = 五选一(添水/灵体外质/贤者之石/天鹅绒颈圈/异蛇之眼)    # 各 20%
  [槽3] = Rng 掷 100：
    0-49  → 尘封魔典（SetupForPlayer(Owner) → RelicOption）
    50-79 → 符文金字塔
    80-99 → 角色专属池：
      基础池 = 该职业两件（铁甲=符文立方体+痛楚印记；静默=悬浮风筝+袖剑；故障=核能电池+机械臂；
              储君=月亮糕点+迷你储君；亡灵=书签+象牙麻将牌）
      + 交换开关：铁甲/故障池互换痛楚印记与核能电池
      + 储君/亡灵递进：已拥有(Owner.Relics)其1 → 加入第三件（橙色团块/大帽子）；
                        已拥有其2 → 只剩最后一件；已拥有其三 → 槽3 改为 魔典62.5%/符文金字塔37.5%
      → Rng.NextItem(池) 各 1/2（或 1/3）概率
  AllPossibleOptions（同步 patch）：槽1池+槽2池+符文金字塔+尘封魔典+6 新遗物+6 塔2 rare（供图鉴/统计）
```

### 3.3 职业关闭 → 原版逻辑回退（107/111 各回各的原版）

- Prefix 中按 `Owner.Character` 判断开关；关闭 → 反射读 `Darv._validRelicSets`（private static，字段名两版一致，内容按版本自适应）→ 逐字复刻原版流程（filter → NextItem → UnstableShuffle → NextBool → 2+魔典 / 3）。
- 守卫：字段缺失/改名 → 整个 mod 停用新逻辑并告警（不 patch 时游戏自然跑原版）。

### 3.4 设置界面（ritsulib）

- 语言：`CreateModLocalization`（eng/zhs/zht 三份 json）+ `ModSettingsText.I18N`——**自动按游戏语言切换**（游戏内切语言即时生效）。✅ 已调研确认（../3.DOCS/007-T-RitsuLib设置多语言与重启方案.md）。
- ① 5 个职业开关：`AddToggle` × 5，`ModSettingsValueBinding`（SaveScope.Global，独立 key）。
- ③ 交换开关：`AddToggle` + I18N 说明。
- ② **"保存并退出"按钮**：`AddButton("保存并退出")` → 回调：保存绑定 → `NGame.Instance.Quit()`（游戏优雅退出，含存档清理）；按钮旁/说明提示"保存时将自动退出游戏"。**不做自动重启**（用户已确认；退出无 Steam 重拉风险）。
- ④ 联机说明条目：`AddSection`/说明文本（I18N）："联机时每个玩家都必须安装本 mod；联机适用性未经测试；每个玩家的概率分布按玩家自己的设置生成"。
- 新局生效：`SubscribeLifecycle<RunStartedEvent>` 时快照设置到静态字段；当前局不受改设置影响。

## 4. 与 RelicGrabBag 的关系（决策后）

- 6 件新遗物 = **Ancient 稀有度 + 不进 SharedRelicPool** → 不进袋 → 只在达弗出现，宝箱/商店/精英永不随机出（方案甲，用户已确认）。
- 因此"利用去重机制"在本 mod 的落点：**无需去重**（Ancient 稀有度天然与随机池隔离，官方达弗 12 件同此现状）。
- 已知边界（官方同样存在，记录不处理）：达弗选项不查袋/不查已拥有（除储君/亡灵契约师的递进逻辑外），同一局内玩家可能重复获得同一达弗遗物（官方现状；用户设计的递进逻辑已覆盖储君/亡灵契约师池的重复，其他池未要求）。

## 5. 风险与提示（更新）

1. **退出方案**：`NGame.Instance.Quit()` 优雅退出（保存窗口/设置/进度、清缓存）；无进程重拉，无 Steam 风险。✅
2. **重启非必需**（记录）：设置运行时读取，新局自然生效；"保存并退出"是 UX 要求（确保下次启动时干净应用全部设置）。
3. **职业回退的版本差异**：107 与 111 原版池不同（9 vs 11 集合），回退后表现不同——用户已确认（"各回各的"）。
4. **多人**：设置本机保存；达弗每玩家独立生成选项（游戏机制）；`affects_gameplay: true` → 联机需全员安装（设置页已加说明条目）；各玩家按自己设置与自己的"已拥有"判定生成。联机适用性未经测试（说明文案如实告知）。
5. **袖剑星费**：塔2 星费体系（储君机制）；0 费判定沿用能量费（AllForOne 写法），星费攻击牌极少——实现期验证并记录。
6. **素材**：塔1 图 128×128 与塔2 图集风格不同，打包前按塔2 规范处理（实现期细节）。
7. **塔2 状态牌**：塔1/塔2 的 Wound 行为一致（均无虚无）——效果照搬无落差（已修正此前误述）。
