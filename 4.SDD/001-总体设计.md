# 001 总体设计

- 项目：重做达弗（`DarvRelicPoolMod`）v1.0.0
- 代码基线：`9.SRC/DarvRelicPoolMod/`，共 27 个 `.cs`（约 2000 行）
- 依赖：游戏《杀戮尖塔2》（v0.107.x / v0.111.0+）、基础库 `STS2-RitsuLib ≥ 0.5.14`、NuGet `Krafs.Publicizer`（仅构建期）
- 相关文档：决策见 `1.ADR/`（001 范围与路线、002 设计 v2、003 实现与构建链）；机制依据见 `3.DOCS/005-T`、`006-R`、`008-T`

## 1. 设计目标

`3.DOCS/005-T-达弗现状机制与双版本差异.md` 记录的现状问题是：原版达弗的三个选项由静态集合 `_validRelicSets` 洗牌取前若干件，没有任何权重概念，107 与 111 的集合数量不同（9 / 11），因此会出现「三个选项同时低收益或负收益」的组合。本 mod 的设计目标（1.ADR/001、1.ADR/002）：

1. 用固定的三槽位结构替代原版随机集合，压低「三选项全废」的概率；
2. 引入《杀戮尖塔1》的 BOSS 遗物，并按职业划分专属池；
3. 槽位 2 统一为加费类遗物、槽位 3 保留原版 50% 尘封魔典；
4. 在 107 与 111 上行为一致（统一覆盖，不读原版池）；
5. 通过设置页让玩家按职业开关与局部互换，关闭即回退该版本原版逻辑。

## 2. 系统架构

mod 只做三件事：**替换达弗的选项生成**、**替换达弗的「全部可能选项」枚举**、**向 `ModelDb` 注册新遗物**；其余（图鉴外观、设置写入语义、图标镜像）都是围绕这三点打的补丁。

```
ModEntry.Initialize()                       ← [ModInitializer]，唯一入口
├── ModTypeDiscoveryHub.RegisterModAssembly  ← 把本程序集交给 RitsuLib 的类型发现
├── RitsuLibFramework.GetDataStore(...)      ← 注册 settings.json（SaveScope.Global）
├── DarvSettingsUi.Register()                ← 设置页（三语 + 保存并退出）
├── patcher（必选，失败即禁用 mod 行为）
│   ├── DarvOptionsPatcher            → Prefix  Darv.GenerateInitialOptions
│   ├── DarvAllPossibleOptionsPatcher → Prefix  Darv.AllPossibleOptions
│   └── WristBladeCompatPatcher       → Postfix AbstractModel.ModifyDamageAdditive（双版本可选）
└── cosmeticPatcher（可选，失败不影响玩法）
    ├── RelicCollectionOutlinePatcher → Postfix NRelicCollectionEntry._Ready
    ├── RelicCollectionSortPatcher    → Postfix NRelicCollectionCategory.LoadRelics
    ├── SettingsPendingResetPatcher   → Prefix  RitsuModSettingsSubmenu.OnSubmenuOpened/Closed
    └── NRelicMirrorPatcher           → Postfix NRelic._Ready
```

必选与可选两组分别由 `RitsuLibFramework.CreatePatcher(ModId, "darv")` 与 `CreatePatcher(ModId, "darv_cosmetic")` 创建，最后 `ApplyRequiredPatcher` 检查必选组：任一项没打上就记一条 `Log.Error` 并放弃 mod 行为（`ModEntry.cs`）。

## 4. 核心数据流：达弗选项生成

入口是 `DarvOptionPool.Generate(Darv darv, Player owner)`，由 `DarvOptionsPatcher` 的 Prefix 调用并短路原方法：

1. **取设置与角色**：`DarvSettings.Current`（每次直接读磁盘态，不做快照），`owner.Character.Id.Entry` 转大写。
2. **回退判定**：角色不在五职业内，或该职业开关为关 → `VanillaFallbackPool.Generate`。
3. **符文金字塔双次判定**：先 `rng.NextDouble() < 0.2` 决定是否占槽位 1；未命中再掷 0.2 决定是否占槽位 2。两槽位互斥，合计约 36%（`1-(0.8×0.8)`）。
4. **槽位 1 / 槽位 2**：未命中金字塔时用 `rng.NextItem` 在池内均等抽取；槽位 2 的池会按角色的异蛇之眼开关剔除 `SneckoEye`（关掉后四件各 25%）。
5. **槽位 3**（`MakeSlot3Option`）：
   - 先算 `tomeAvailable = HasAncientCards(owner)`（与 `DustyTome.SetupForPlayer` 同一筛选条件：卡池里有 `CardRarity.Ancient` 且不属于 `ArchaicTooth.TranscendenceCards`）；
   - 再算 `characterPool`：铁甲/静默/故障各 2 件（可被互换开关调换铁甲与故障的对应件），储君/亡灵按「已持有稀有版」剔除对应先占版；
   - 池空（储君/亡灵三件稀有全持有）→ 100% 魔典；魔典不可用则极端兜底金字塔并 `Log.Warn`；
   - 正常掷 `rng.NextDouble() * 100 < 50` → 魔典（`SetupForPlayer(owner)` 后包装成选项）；否则角色池均等抽取。
6. **包装**：`darv.RelicOption(relic.ToMutable())` 生成 `EventOption`。

所有随机都取自 `darv.Rng`（事件自带随机源），不新建 `Rng`，因此同一局的重放/种子语义与游戏一致。

## 5. 补丁策略

| 补丁 | 目标 | 方式 | 必要性 | 关键约束 |
|---|---|---|---|---|
| `DarvOptionsPatcher` | `Darv.GenerateInitialOptions` | Prefix，直接 `__result = ...` 并跳过原方法 | 必选 | 两版本签名一致，无需版本分支 |
| `DarvAllPossibleOptionsPatcher` | `Darv.AllPossibleOptions`（getter） | Prefix 替换枚举 | 必选 | 必须与生成器池保持一致，否则图鉴与控制台会漏项 |
| `WristBladeCompatPatcher` | `AbstractModel.ModifyDamageAdditive` | Postfix ×2（5 参与 6 参） | 必选 | 目标按「方法名 + 参数类型数组」运行时反射解析，缺失即 `ignoreIfMissing` |
| `RelicCollectionOutlinePatcher` | `NRelicCollectionEntry._Ready` | Postfix | 可选 | 仅在 `ModelVisibility.Visible` 上角色色 |
| `RelicCollectionSortPatcher` | `NRelicCollectionCategory.LoadRelics` | Postfix 重排子分类节点 | 可选 | 顺序：铁甲 2 → 静默 2 → 储君 3 → 亡灵 3 → 故障 2 |
| `SettingsPendingResetPatcher` | `RitsuModSettingsSubmenu.OnSubmenuOpened/Closed` | Prefix 清暂存 | 可选 | 刻意不 hook `OnSubmenuHidden/Shown` |
| `NRelicMirrorPatcher` | `NRelic._Ready` | Postfix 对子节点做水平镜像 | 可选 | 只处理 `DARV_RELIC_POOL_MOD_RELIC_ANCIENT_*`，尺寸未就绪时延迟一帧 |

## 6. 数据结构

`DarvSettings`（JSON 持久化到 `settings.json`，`SaveScope.Global`）：

| 字段 | 默认 | 语义 |
|---|---|---|
| `IroncladEnabled`…`NecrobinderEnabled`（5 项） | `true` | 该职业是否用本 mod 逻辑；关 = 回退该版本原版 |
| `SwapMarkOfPainNuclearBattery` | `false` | 铁甲的痛楚印记 ↔ 故障的核能电池互换 |
| `SneckoIronclad`…`SneckoNecrobinder`（5 项） | `true` | 该职业槽位 2 是否可能出现异蛇之眼 |

`DeferredSaveBinding` 的状态只有两个：磁盘值（`DarvSettings.Load()`）与本会话暂存 `bool? _pending`。

## 7. 设置写入语义

这是本项目返工最多的部分（1.ADR/003 修复记录 4、5、8、9、10、11、12），最终语义为「**暂存 + 保存并退出唯一落盘**」：

- `Read()` = `_pending ?? 磁盘值`；
- `Write(v)` 只写 `_pending`，不碰 `ModDataStore` 内部实例（历史教训：直接改内部实例会让任何一次 `store.Save` 意外落盘）；
- `Save()` 空操作，用来阻断 RitsuLib 设置页 0.35s 防抖的自动保存；
- 只有「保存并退出」按钮会把暂存覆盖到磁盘 → `ClearPending()` → `NGame.Quit()`；
- 打开/关闭设置界面时 `SettingsPendingResetPatcher` 清空暂存并同步蛇眼按钮显示，保证重进设置页看到的是磁盘值。

## 8. 遗物实现要点

- 塔1 六件：继承游戏 `RelicModel`，`Rarity = Ancient`，override `IconBaseName`/`BigIconPath` 指向 `res://DarvRelicPoolMod/images/relics/*.png`；不注册进角色池（否则会进 `RelicGrabBag`，见 `3.DOCS/006-R`）。
- 先古六件：同样 reuse 官方图集帧（`IconBaseName` 返回官方帧名，保留 `AtlasTexture` 的 region/margin 元数据），方向由 `NRelicMirrorPatcher` 在渲染层翻转；`AfterObtained()` 里 `Owner.RelicGrabBag.Remove(稀有版)` 实现单向互斥，反向互斥由选项池的「已持有则剔除」实现。
- 描述文本使用游戏自身的动态变量格式化：`{Stars:starIcons()}`、`{Energy:energyIcons()}`、`[gold]…[/gold]` 等；改文案时 token 拼错不会编译报错，只在游戏内显示异常（修复记录 14 的教训）。

## 9. 异常处理与兜底

| 场景 | 行为 |
|---|---|
| 未知角色（mod 角色/未来新角色） | 走 `VanillaFallbackPool` |
| 某职业开关关闭 | 走 `VanillaFallbackPool`，数据源为当前版本的 `_validRelicSets` |
| 角色池为空（储君/亡灵稀有全持有） | 槽位 3 = 100% 尘封魔典 |
| 角色没有先古稀有卡（魔典不可用） | 槽位 3 = 100% 角色池，`Log.Warn` |
| 两者同时不可用 | 槽位 3 = 符文金字塔，`Log.Warn`（注释标注为理论不发生的极端兜底） |
| 必选补丁未打上 | `ApplyRequiredPatcher` 记 `Log.Error`，放弃 mod 行为 |
| 可选补丁未打上 | 记日志，玩法不受影响 |

## 10. 兼容策略

- **双版本统一覆盖**：选项池完全由 mod 定义，不读原版集合结构，因此 107/111 行为一致。
- **虚方法签名差异**：`ModifyDamageAdditive` 在 107 为 5 参、111 为 6 参。若用 `override` 写死某一版，另一版虚分派不到且**静默失效**（不报错、不崩溃）。因此袖剑完全不用 `override`，改为两条 optional patch 在运行时按参数类型解析。
- **编译期依赖**：工程直接引用游戏目录的 `sts2.dll`，切分支后本地 dll 即换版，所以任何跨版本差异都不能靠编译期条件。
- **增量版本**：manifest 声明 `min_game_version 0.107.0` 与 `STS2-RitsuLib ≥ 0.5.14`；无重大 API 变更时无需改代码。

## 11. 构建与资源

`build.ps1` 串联：`dotnet build` → Godot `--headless --import` → `--export-pack` → 拷贝 dll/pdb/pck/json 到游戏 `mods/DarvRelicPoolMod/`。

pck 侧有两条必须遵守的约束（1.ADR/003 修复记录 2、16）：

1. 所有 mod 资源必须带 `res://DarvRelicPoolMod/` 前缀，否则会与游戏主 pck 同路径冲突并**覆盖官方本地化表**，且不会被 `ModManager.GetModdedLocTables` 合并；
2. `export_filter` 必须用 `selected_resources`，`resources` 在 headless 导出下会解析为空。

## 12. 测试方案

手动测试方案见 `3.DOCS/010-T-手动测试方案.md`：控制台 `ancient DARV` / `ancient DARV <关键字>` 进入事件，按槽位统计分布，逐项验证六件塔1 遗物、六件先古遗物、设置开关与回退、图鉴光效与排序、三语切换、107 双版本。本项目**没有自动化测试**：游戏内行为依赖运行时注入，当前没有可用的测试宿主。
