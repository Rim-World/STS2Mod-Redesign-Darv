# ADR-001：达弗修改 mod 需求决策（范围/路线/双版本）

- 状态：已接受（2026-08-23，用户决策）
- 背景：用户要开发《杀戮尖塔2》mod，修改先古之民"达弗（Darv）"的选项概率分布与内容，同时适配 default 107 与 beta 111。本 ADR 记录 2026-08-23 资料收集阶段后用户对四个方向性问题的决策。

## 决策

1. **修改范围：概率 + 内容都改（重构达弗选项池）**
   - 不再沿用原版 `_validRelicSets` 的 9/11 集合结构；mod 自定义整个选项池（遗物清单、权重、按幕/条件过滤、选项数量、DustyTome 掺入逻辑），并同步维护 `AllPossibleOptions`。
   - 原版机制事实（见 ../3.DOCS/005-T-达弗现状机制与双版本差异.md）：无权重概念（均匀随机），"概率分布"完全由集合结构+filter+50% NextBool 决定。

2. **塔1遗物引入：待定（先不定）**
   - 用户需先阅读候选清单再圈定。已备 18 件主推候选 + 5 备选（../3.DOCS/003-T-塔1遗物对照表.md §5），另附决策辅助对比表（../3.DOCS/004-T-塔1遗物候选细节.md）。
   - 待用户圈定后才进入遗物实现设计，不阻塞整体架构。

3. **技术路线：ritsulib 为主**
   - 依赖 STS2-RitsuLib（工作坊 0.5.14，lib/ 含 0.107.1/0.111.0 兼容变体）：
     - 塔1遗物本体注册：`RegisterRelic<TPool,TRelic>` / `.Relic<TPool,TRelic>()`（若引入）。
     - 达弗选项追加（若采用"追加"粒度）：`AncientOption<Darv>`（只增不减，Postfix 挂 GenerateInitialOptionsWrapper）。
     - 达弗池/概率重构（本 mod 核心）：`RitsuLibFramework.CreatePatcher(modId, name)` + `IPatchMethod` 自写 Harmony patch，Prefix 整体替换 `Darv.GenerateInitialOptions`（统一覆盖）与 `AllPossibleOptions`。
     - 本地化/配置/存档/调试面板：ritsulib 现成 API。
   - 不依赖 BaseLib（ritsulib 与其互操作，但本 mod 不需要 BaseLib 能力；如后续需要遗物图标覆盖等再评估）。
   - 动机：不重复造轮子；ritsulib 是唯一提供"向既有 Ancient 追加选项"专门 API 的库，且 patch 脚手架（PrivateAccess/HarmonyIl/动态 patch）成熟；用户环境已装。

4. **双版本策略：统一覆盖**
   - 107 与 111 上 mod 行为完全一致：选项池/权重/幕条件/DustyTome 逻辑均由 mod 定义，不读取各版本原版 `_validRelicSets`。
   - 简化兼容：`Darv.cs` 的实例方法/字段两版签名一致（仅 static ctor 内容不同），Prefix 替换无需版本分支；仍保留用户已有 mod 的"懒评估守卫"模式（存在性检查，防止未来版本改动导致崩溃）。

## 后果
- 实现阶段依赖 ritsulib 版本跟进（游戏更新后 ritsulib 需更新，工作坊自动更新）。
- 玩家需装 RitsuLib（manifest 声明依赖），但用户环境与工作坊分发均无门槛。
- 塔1遗物清单未定 → 选项池的具体组成未定，但架构（配置驱动的池定义）不依赖具体清单。
