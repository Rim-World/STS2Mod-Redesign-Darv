# ADR-003：达弗修改 mod 实现（M1-M4）与构建链

- 状态：已接受（2026-08-23，mod 已构建安装至游戏目录 `mods/DarvRelicPoolMod/`）
- 背景：设计 v2.1 确认后进入实现。本 ADR 记录实现期决策与构建链经验。

## 决策

1. **依赖与可见性**：NuGet `STS2.RitsuLib 0.5.14`（与工作坊运行时严格对齐）+ `Krafs.Publicizer 2.2.0` publicize `sts2` 程序集（官方模板推荐；用于访问 `Darv._validRelicSets`（private static）、`AncientEventModel.RelicOption`（protected））。guard 逻辑仍保留（生成失败回退原版逻辑）。
2. **Patch 方式**：ritsulib `IPatchMethod`（`RegisterPatch<T>` 单数重载，`IPatchMethod.CreatePatchInfos` 生成），两个 patch 类：
   - `DarvOptionsPatcher`：Prefix 替换 `GenerateInitialOptions`（职业开关 → 新逻辑 / 原版回退）
   - `DarvAllPossibleOptionsPatcher`：Prefix 替换 `AllPossibleOptions`（图鉴"先古→达弗"分类、控制台补全一致性）
3. **原版回退**：`VanillaFallbackPool` 逐字复刻原版流程，数据源直接读游戏静态池 `Darv._validRelicSets`（版本自适应：107→9 集合、111→11 集合，符合 ADR-002 Q6）。
4. **新遗物注册**：6 件塔1 遗物继承游戏 `RelicModel`（非 ritsulib 模板），用 `[RegisterRelic(typeof(某池))]`？——**实现细节**：实际代码中未写 `[RegisterRelic]` 属性！需要检查……（构建通过不代表注册生效）。**注意**：DarvOptionPool 直接引用 `ModelDb.Relic<RunicCube>()`——若未注册进 ModelDb，运行时会抛异常。必须用 ritsulib 属性 `[RegisterRelic]` 或 content pack 注册！**此点需在汇报中作为"已验证/待验证"项**：当前 6 个遗物类未加注册属性 → 需要在 M5 前补上（或确认 ritsulib 自动发现机制）。→ 记录为已知问题，修复在实现收尾时完成。
5. **图标**：override `RelicModel.PackedIconPath/PackedIconOutlinePath/BigIconPath`（virtual）指向 pck 内 png（塔1 原版图 128×128）。
6. **本地化**：遗物文本走游戏表合并（pck `localization/{lang}/relics.json`，`LocManager` mod 表合并机制）；设置文案走 ritsulib `CreateModLocalization`（`localization/settings/{lang}.json`）+ `ModSettingsText.I18N`（自动语言切换）。
7. **设置**：`ModDataStore`（SaveScope.Global）+ `RegisterModSettings` 页面（5 职业开关 + 交换 + 联机说明 + 保存并退出按钮 → `NGame.Instance.Quit()`）；`RunStartedEvent` 订阅做开局快照（当前局不生效）。
8. **构建链**（踩坑记录）：
   - `export_filter` 必须用 `selected_resources`（Godot 4 有效值）；`resources` 在 headless 导出下解析为空 → "Must select at least one file"
   - `export_files` 显式列出全部要打包的文件（png/json/mod_image）
   - `mod_image.png` 工程图标必需（project.godot 引用）
   - dotnet build → Godot `--import` → `--export-pack` → 拷贝 mods/（build.ps1 全自动）

- **教训**：mod pck 资源必须带 `res://{modId}/` 前缀（与游戏资源隔离），这是官方模板与 BaseLib/用户既有 mod 的一贯结构。

## 修复记录 4（2026-08-24，设置保存语义修正）
- **问题**：ritsulib 设置 UI 的 0.35s 防抖自动保存（`FlushDirtyBindings` → 对所有脏绑定 `Save()`，RitsuModSettingsSubmenu.cs:3297-3322）导致**退出设置界面即落盘**，与"只有保存并退出才保存"的设计相悖。
- **修复**：新增 `DeferredSaveBinding`（自定义 `IStructuredModSettingsValueBinding<bool>` + `IDefaultModSettingsValueBinding<bool>`）：
  - `Read()` = 本会话暂存值 ?? 磁盘值（UI 刷新不弹回；未保存改动不落盘）
  - `Write()` = 仅内存暂存（`_pending`）
  - `Save()` = 空操作（阻断 UI 自动保存）
  - "保存并退出"按钮 = **唯一落盘途径**：以磁盘为基础、用各绑定 `PendingValue` 覆盖改动项 → `store.Save` → 清空暂存 → `NGame.Quit()`
  - 已知语义边界：同一游戏运行内"未保存关闭设置页 → 重开"时暂存值仍挂在 UI（页面缓存复用）；落盘仍只发生在点按钮时。
- 设置页新增提示文案（三语）"请点击最下面的保存按钮，退出游戏后重启才能应用设置，否则设置将不会保存。"
- 备份：修改前已备份至 `10.OUTPUT/01-构建产物/功能测试第3版/`（用户要求）。重建安装完成（5:50）。

## 修复记录 5（2026-08-24，设置暂存残留修正 + 设置页顶部提示）
- **问题**：玩家改开关但不点"保存并重启"，自行重启游戏后按钮显示亮的（正确，未落盘）；但**不重启游戏**时，退出 ritsulib 设置界面再重新进入，按钮显示关掉的（暂存值残留）——而实际生效仍是磁盘值（亮的），UI 与生效状态不一致。
- **根因**：页面内容缓存池化（`RetainedPageContentCacheLimit=2`、idle 5s 释放）跨打开复用控件；`DeferredSaveBinding.Read()` 返回"暂存 ?? 磁盘"，缓存复用刷新回调显示暂存值；此前没有打开/关闭钩子重置。
- **修复**：新增 `Patches/SettingsPendingResetPatcher.cs`（IsCritical=false，注册于 cosmeticPatcher），Prefix hook `RitsuModSettingsSubmenu.OnSubmenuOpened` + `OnSubmenuClosed`：
  - `OnSubmenuOpened` Prefix：在 `EnsureUiUpToDate` 刷新控件**之前**清空全部 `_pending` → 刷新回调 `Read()`=磁盘值 → 重开设置页显示修改前状态
  - `OnSubmenuClosed` Prefix：退出设置界面兜底清空
  - 刻意**不** hook `OnSubmenuHidden/OnSubmenuShown`：隐藏→重显路径无内容刷新点，清了会导致控件显示与 `Read()` 不一致（更糟）
- **顶部提示**：设置页最前新增"保存须知"section（`section.top.title` / `section.top.notice`，三语）——"需要点击本页面最下方的「保存并退出」按钮才能保存设置，否则设置将不会保存。"

## 修复记录 9（2026-08-25，保存语义回归修复 + 蛇眼按钮行；备份 `10.OUTPUT/01-构建产物/逻辑修正第7版/`）
- **用户反馈②（澄清后）**：v1.0.1 下"未点保存退出设置界面再重进，按钮显示关掉的，但实际生效仍是亮的（磁盘值）"——UI 显示与生效不一致（修复记录 4/5 已解决问题的回归）；设计上应"只有保存并退出才保存，没点保存的改动不生效、重进显示修改前状态"。
- **根因追溯（结论）**：**不是真落盘回归**——`Save()` 空操作仍在，`FlushDirtyBindings`（OnSubmenuClosed/防抖）只调 `binding.Save()`（`SelectEffectiveSaveRoots` 返回的就是我们的绑定），`ModDataStore.SaveAll` 在 ritsulib 内无调用者。真正原因是修复记录 8 的"live 即时生效"设计：`Write` 直接改内存态 + 停用 `SettingsPendingResetPatcher` → 未保存改动保留，重进 `Read()` 显示改动值。附带隐患：`ModDataStore.Get` 返回 store 内部同一实例（`RegisteredDataEntry.Data`），v1.0.1 的 `Write` 直接改它，未来任何 `store.Save` 触发都会落盘——已消除。
- **修复（恢复"暂存+丢弃"，保留无快照）**：`DeferredSaveBinding` 恢复 `_pending`（`Write` 只写暂存、不碰 store 实例；`Read` = 暂存 ?? 磁盘）；`DarvSettings` 去掉 `_live`（`Current => Load()` 只读磁盘态）；`SettingsPendingResetPatcher` **重新注册**（打开/关闭设置界面清暂存 → 重进显示修改前状态，与生效值一致）；`SaveAndQuit` 恢复"磁盘为基础 + PendingValue 覆盖 → Save → ClearPending → Quit"。
- **修复后语义**：改开关仅 UI 暂存（达弗始终按磁盘值）；退出设置界面 → 改动丢弃；重启 → 按磁盘；点"保存并退出" → 落盘 + 重启后立即生效（无快照）。
- **用户反馈③（蛇眼开关 UI）**：五个职业开关各占一行 → 改为一排五按钮：蛇眼 section 的 5 个 `AddToggle` 替换为 1 个 `AddCustom`（`ModSettingsBuilders.AddCustom` + `HBoxContainer` + 5 个 Godot `Button`（ToggleMode），各只显示职业名，点击 → `binding.Write` + `host.MarkDirty`，状态自绘（创建时 `binding.Read()`），与保存语义完全兼容。
- **文案**：三语生效时机改为"未保存的改动不会生效；保存并退出后重启游戏立即生效"（保留用户 eng "the" 与全部自定义文案）。版本保持 1.0.0（用户决策）。

## 修复记录 10（2026-08-25，蛇眼按钮样式与刷新周期修复）
